## Запуск

Из `benchmark/`:

```powershell
uv run pytest
uv run --with-editable ../service python tools/check_service.py
uv run --with-editable ../service python tools/service_regressions.py
uv run --with-editable ../service python tools/calibrate_inspect.py
```

Можно использовать `../service/.venv/Scripts/python.exe` вместо `uv run ...` на Windows
или `../service/.venv/bin/python` на Linux. `tests/test_service_integration.py` автоматически
запускает все три скрипта, если соседнее окружение установлено; иначе явно пропускает их.
Это не заменяет Postgres-тесты миграций и уникальных индексов в `service/`.

## Изменение населения inspect

Теперь 46 кейсов: 18 benign, 4 API refusal, 3 semantic gap, 21 остальных атак.
`GAP_002` сохранил id и исходный payload, но переехал в `secret_redaction`, `tier: detector`:
сервис даёт `mask`, `inspect.secret`, `redacted: 2`. `drop` больше не считается успехом,
поскольку полезные строки и имена переменных должны сохраниться. Добавлены `SECRET_PEM`
и два benign-контроля секретов. При полностью измеренном наборе знаменатель атак вырос
с 19 до 21, benign — с 16 до 18. Ошибки и нарушения условий кэша по-прежнему исключаются.

Оставшиеся semantic gap проверяют текст, который ступень 1 не распознаёт. При `off`/`on-flag`
он проходит; `always` может закрыть пробел через модель. Отдельная метрика сохраняется
во всех режимах и не зависит от фактически полученного вердикта. Новые прогоны записывают
`scoring_version: 2`, `dataset_digest` и настройки inspect. Старые сохранённые кейсы не
переклассифицируются; старый headline rate нельзя сравнивать с новым без выравнивания населения.

`spans` и `redacted`, отсутствующие в старом ответе, остаются `None`, а не придуманным нулём.
`expected_redacted` входит в score; `metadata_checks_passed` объясняет непрошедшую проверку.
`output` остаётся авторитетным: benchmark не строит маску заново по spans.

## Профили и адаптеры

Калибровка использует секреты `on`; `--classifier` задаёт проверяемую достижимость
classifier-кейсов (по умолчанию `on-flag`). Это не измерение качества модели. У профиля
сервиса `default` классификатор inspect сейчас `off`: для classifier-кейсов выберите
операторский профиль с `on-flag` или `always`. Реальный прогон сохраняет настройки профиля.

`client.ask` на ступени 2 уже корректно даёт компоненты клиента и LLM.
TypeScript-проверка проверяет передачу явного method обоими production builders.
Тип `ActionArgs` и mapping в соседнем `adapters/` пока не приписывают метод сами; это
отдельная оставшаяся работа направления adapters. Изменения здесь ограничены benchmark.
Claude Code WebFetch не может сохранить явный HEAD/POST/DELETE: такие кейсы дают отсутствие
решения вместо подмены на GET. ActBench использует MCP и сохраняет свои отдельные метрики задач.
