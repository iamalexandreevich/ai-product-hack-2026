# Инсталлер: коротко

Запускается из репозитория — в npm ничего не публиковалось:

```bash
node adapters/packages/installer/bin/openmagi.js <команда>
```

После первой установки та же программа лежит в `~/.local/bin/gate`, дальше просто `gate`.

## Установка

**Гард уже где-то поднят** — самый частый случай:

```bash
openmagi install --guard-url https://ваш-гард --token <ключ> --level medium --yes
```

**Поднять гард заодно** — локально, через docker compose:

```bash
openmagi install --start-guard \
  --llm-url https://api.example/v1 --llm-model my-model --llm-key <ключ> \
  --level medium --yes
```

Инсталлер сам сгенерирует токен, поднимет контейнеры из `service/` и дождётся, пока
`/healthz` ответит. LLM нужен ступени 2; без ключа ступень 1 работает, а ступень 2
честно падает в `ask`.

## Команды

| Команда | Зачем |
|---|---|
| `openmagi install` | Найти агентов и поставить каждому команду `<агент>-gate` |
| `openmagi status` | Что установлено, какой режим, жив ли гард |
| `openmagi doctor` | Что сломано и как чинить |
| `openmagi mode <режим>` | Сменить строгость: `auto`, `ask`, `allow`, `off` |
| `openmagi uninstall` | Снять всё; рабочие агенты вернутся как были |

## Флаги установки

| Флаг | Зачем |
|---|---|
| `--guard-url URL` | Адрес уже поднятого гарда |
| `--token T` | Ключ к нему |
| `--start-guard` | Поднять гард локально вместо подключения к чужому |
| `--llm-url`, `--llm-model`, `--llm-key` | Модель для ступени 2 при `--start-guard` |
| `--level low\|medium\|high` | Строгость детерминированных правил (по умолчанию `medium`) |
| `--only kilo,codex` | Поставить не всем, а перечисленным |
| `--profile P` | Профиль политики на стороне гарда |
| `--yes` | Не переспрашивать |

Агенты: `opencode`, `kilo`, `opencode2`, `pi`, `codex`, `dsh`.

## Что получается

У каждого агента появляется вторая команда. Разница — только суффикс:

```
kilo          ваш обычный, без гейта
kilo-gate     он же, но каждый тулкол через гард
```

Ваши рабочие агенты не трогаются: ни строчки в их конфигах.

## Уровни защиты

`--level` пишет `~/.config/gate/rules.json` — три группы для детерминированной ступени:

- **low** — запрещено только заведомо разрушительное;
- **medium** — плюс секреты и конфиги агентов под запретом, установка пакетов спрашивается;
- **high** — плюс всё, что выходит за рабочий каталог или лезет в сеть, идёт через вопрос.

Один файл на все агенты сразу. **Правьте его руками** — переустановка не перезапишет,
изменения подхватываются со следующего решения.

## После установки

```bash
openmagi status
```

Проверить, что гейтит:

```bash
kilo-gate run "покажи содержимое файла .env"
```

Агент попробует прочитать, гард откажет, агент объяснит причину. Обычный `kilo` тот же
файл прочитает.

**Для Codex нужен один разовый шаг:** запустите `codex-gate`, на экране Hooks нажмите `t`.
Codex не запускает неподтверждённые хуки и молчит об этом — `openmagi doctor` предупредит.

## Если что-то не так

```bash
openmagi doctor
```

Три частые причины: `~/.local/bin` не в `PATH`; неподтверждённые хуки Codex; залипший
процесс от прошлого запуска — он переживает закрытие окна, лечится
`pkill -f "$HOME/.local/share/gate/"`.

## Патченный билд для opencode и Kilo

Нужен, потому что у них хук `permission.ask` объявлен, но не вызывается. Без билда
установка уходит в `fallback`: `deny` работает, но промпт мигает и часть запросов идёт
мимо гейта.

```bash
adapters/build/build.sh kilo https://github.com/Kilo-Org/kilocode.git v7.5.6
```

Версия bun обязана совпадать с той, что пинит репозиторий агента; скрипт проверит и
остановится с точной командой. Это не перестраховка: сборка чужим bun проходит смоук-тесты,
работает headless и под tmux — и не рисует TUI в настоящем терминале.

Подробности: [MANUAL-TESTING.md](MANUAL-TESTING.md) — что и как проверять,
[ARCHITECTURE.md](ARCHITECTURE.md) — как устроено.
