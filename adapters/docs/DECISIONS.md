# Ключевые решения (лог)

Почему сделано именно так — то, что не видно из кода. Кратко; детали в
`MANUAL-TESTING.md`.

1. **Один core, шесть тонких адаптеров.** `packages/core` — вся логика (клиент, маппинг тулов,
   режимы, политика, кэш, лимиты), ноль зависимостей от харнесса. Адаптеры (plugin-v1, plugin-v2,
   plugin-pi, plugin-codex, plugin-dsh) только переводят события харнесса в вызовы core. Чтобы правила режимов и fail-open
   не разъезжались между харнессами.

2. **Node ≥22.6 нативный TS, без сборки, тесты `node --test`.** Ноль зависимостей в рантайме и
   тестах → быстро, воспроизводимо, ничего не тянем. Бандлим только для публикации v2 (bun).

3. **Контракт: `/v1/decide` эталон, `/v1/inspect` по аналогии.** Источник правды — `contracts/openapi.yaml`
   (генерируется из работающих моделей сервиса; корневой `openapi.yaml` — устаревшая копия). `in`-эндпоинта у гарда пока нет → делаем совместимый по форме, транспорт
   в конфиге. Не тащим `/check`/`direction`/историю из первоначального ТЗ. Дыры → `contract-gaps.md`.

4. **Fail-open только при недоступности, не при плохом ответе.** Плохой ответ гарда → `ask`
   (никогда `allow`, как требует openapi). Нет ответа вообще → локальная политика `on_unavailable`.

5. **Патч 1.x/Kilo обязателен и подтверждён.** `permission.ask` реально мёртв → оживляем reviewer'ом.
   reviewer в **замыкании слоя** (не InstanceState — иначе «InstanceRef not provided» при конструкции).
   Один коммит (permission+plugin неразделимы). deny — только throw/хук (reject-с-сообщением
   недоступен в v1-клиенте).

6. **opencode2 — БЕЗ патча.** Плагинный API рабочий: `Plugin.define`+`ctx.tool.hook`. Не `{id,server}`
   (это `/v1` compat, runtime не зовёт). Грузится только из npm → verdaccio. Кэш версионный.
   Нет permission-домена → нет нативного `ask` (деградирует в блок).

7. **Pi — БЕЗ патча, самый чистый.** `pi.on("tool_call")` блокирует нативно, `ctx.ui.confirm` = HITL,
   `pi.registerShortcut`. Extension через settings.json.

8. **Обёртка + overlay, оригинал не трогаем.** `<h>-gate` = патченный билд + плагин через
   `*_CONFIG_CONTENT` (Kilo: `KILO_*`, не `OPENCODE_*`). Билд пинится к точной версии (общая SQLite).
   `uninstall` по sidecar-записи снимает ровно наше.

9. **Shift+Tab через `api.command.register({keybind})`** (registerLayer не опубликован), клавиша
   освобождается `keybinds.agent_cycle_reverse:"none"`. Режим в `~/.config/gate/state.json`
   (единственный общий канал сервер↔TUI), mtime-кэш, переключение мгновенно.

10. **Второй слой `in` для ошибок тулов.** `tool.execute.after` не стреляет на упавшем туле (1.x/Kilo)
    → фильтруем ошибочные `tool_result` в `experimental.chat.messages.transform`. В v2 `after`
    приходит и с `error`.

11. **Codex — без патча, плагином через marketplace.** Хуки у Codex штатные (`hooks` = stable),
    но грузятся ТОЛЬКО из установленного плагина: свободный `hooks.json` и `-c hooks.*`
    игнорируются (проверено на 5 путях). Плагин Codex **копирует** к себе в кеш, поэтому core
    вендорится внутрь плагина (`sync-core.sh`), а не резолвится из воркспейса. Хук не запускается
    без подтверждения (`trusted_hash` считается по конфигурации обработчика: правка скрипта
    повторного подтверждения не требует, добавление хука — требует).

12. **Codex 0.146 реализует меньше, чем публикует.** В PreToolUse работает только `deny`;
    `allow`/`ask`/`updatedInput` отклоняются рантаймом, `updatedMCPToolOutput` в PostToolUse — тоже.
    Отсюда раскладка на три скрипта: `pre` = hard-deny, `perm` (PermissionRequest) = авто-одобрение
    и HITL, `post` = `decision:"block"` вместо подмены текста. `ask` на каждый тулкол недостижим:
    PermissionRequest срабатывает только там, где Codex и сам собирался спросить.

13. **DeepSeek Harness — самая чистая интеграция, без патча.** `tools/pre-execute` принимает ровно
    `{allow|deny|ask}`, `tools/post-execute` — `{accept,content}|{block,feedback}`, а `ask` уходит
    в штатный approval-seam харнесса. Ставится записью `insert` в `cordis.patch.yml` профиля.

14. **Fail-open — это «пусть решает харнесс», а не «пропустить».** В dsh `{kind:"allow"}` минует
    собственный approval-seam, поэтому при недоступном гарде адаптер возвращает `next()`. Иначе
    плагин ослаблял бы защиту по сравнению со своим отсутствием.

15. **Патч под Kilo — отдельный, а не общий с opencode.** Kilo переписал
    `packages/opencode/src/permission/index.ts` (557 строк против 223 у upstream: свои
    `ConfigProtection`, `KiloHeadless`, `drain`, сессионные правила), поэтому патч opencode
    на него **не накладывается** (`patch does not apply`). Якоря тоже другие: `ask` возвращает
    `AskOutcome`, ранний выход из авто-одобрения несёт решающее правило, `Service.of` отдаёт три
    лишних метода. Патчи разведены по каталогам `build/patches/<harness>/`, `build.sh` берёт свой.
    Семантика одинаковая — reviewer в замыкании слоя.

16. **`manifest.json` не коммитится.** `build.sh` пишет туда локальные пути и sha свежего билда —
    файл машинно-зависимый. На свежем клоне его нет, инсталлер это переживает и уходит в fallback,
    поэтому перед демо билд надо собрать. То же с вендоренной копией core внутри Codex-плагина
    (генерится `sync-core.sh`) — в `.gitignore`, чтобы не разъезжалась с оригиналом.

17. **Гейтить, не трогая рабочий агент — тремя разными способами.** Цель одна: команда
    `<харнесс>-gate` рядом с нетронутым агентом. Способ диктует сам харнесс. opencode и Kilo —
    патченный билд плюс плагин через `*_CONFIG_CONTENT`. Codex и Pi — **отдельный каталог
    конфигов** через `CODEX_HOME` / `PI_CODING_AGENT_DIR`: файлы, которые мы правим, копируются;
    ключи и история линкуются, чтобы логин был общий; базы не трогаются вовсе (два бинарника на
    одной SQLite мигрируют схему друг под другом). dsh — отдельный профиль, это его родной
    механизм «другой набор плагинов».

18. **TUI-плагин только под обёрткой.** Он писался в общий `tui.jsonc`, который читают обе
    сборки, — и обычный `kilo` показывал бейдж `gate: auto`, ничего не гейтя. Индикатор защиты
    без защиты хуже отсутствия индикатора. Теперь наш tui-конфиг лежит отдельно и подключается
    через `*_TUI_CONFIG` из обёртки.

19. **Плагин подключается путём к бандлу, не npm-спеком.** `@agentgate/gate-plugin` в реестре
    нет; спек молча не резолвился, и плагин не грузился при внешне успешной установке. Инсталлер
    собирает самодостаточный бандл и ссылается на него абсолютным путём. Тест проверяет, что путь
    существует, а не что строка совпала.

20. **Политика ступени 1 — файл пользователя.** `~/.config/gate/rules.json`, три группы
    `allow`/`ask`/`deny`, выбор из трёх уровней при установке, один файл на все харнессы сразу
    и отправка вместе с каждым решением в поле `rules`. Пишется один раз и **не перезаписывается**:
    отредактированная политика переживает переустановку. Не `metadata` — оно по контракту не
    доходит до логики решения; не `profile_id` — профиль на сервере один на всех, а уровень
    выбирает пользователь у себя.

21. **Версия bun для сборки проверяется и блокирует.** Сборка чужим bun проходит все смоук-тесты,
    работает headless и под tmux — и не рисует TUI в настоящем терминале. Рантайм bun
    компилируется внутрь бинарника, а проверка версии в апстримном скрипте нарочно ослаблена до
    каретного диапазона. Стоило почти дня поисков; теперь `build.sh` сверяется с `packageManager`
    репозитория и падает с точной командой.

22. **Инсталлер спрашивает, а не предполагает.** Детект, выбор агентов, выбор гарда (подключиться
    или поднять свой), уровень защиты — и сводка всего, что будет сделано, до первого изменения.
    Промпты на встроенном Node, без зависимостей; ключи читаются без эха. Любой ответ можно задать
    флагом, а `--yes` или неинтерактивный шелл берут умолчания молча.

23. **С решением уходит история диалога, а не только последняя реплика.** Плоский список ходов,
    **от старых к новым**, у каждого — что это (`human`/`assistant`/`toolcall`/`toolresult`) и кто
    написал (`human`/`agent`/`system`). Обратный порядок рассматривали и отвергли: обрезает
    отправитель по объявленному лимиту, а не читатель по ходу чтения, — то, что ушло, и есть
    выбранный хвост. `author` не дублирует `role`: внутри сабагента «человеческую» реплику написала
    родительская модель, и без этого поля классификатор принял бы слова агента за намерение
    пользователя. Обрезка выбрасывает ходы целиком: обрезанный ход читается как полный.
    Форма и лимиты (200 ходов, 128 КБ) — по спеке сервиса, чтобы обе стороны сошлись без
    переговоров.

## Статус: всё из ТЗ готово; 6 харнессов живьём против настоящего гард-сервиса
(`api.openmagi.ru`, 33/33); инсталлер покрывает все шесть с интерактивным мастером;
150 тестов зелёных.
