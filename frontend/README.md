# frontend — сайт openmagi.ru

Направление 4. Лендинг OPENMAGI, который Caddy отдаёт на `openmagi.ru` и `www.openmagi.ru`. Бэкенд живёт отдельно на `api.openmagi.ru` (см. `docs/connect.md`), сайт к API не обращается.

## Что здесь лежит

`site/` — чистая статика без сборщика, ровно то, что отдаётся с сервера:

| Файл | Что в нём | Когда править |
|---|---|---|
| `index.html` | Разметка страницы, тексты по умолчанию на русском | Меняется структура секций |
| `styles.css` | Токены дизайн-системы и все стили | Меняется дизайн |
| `app.js` | Переключение языка, появление по скроллу, скролл-терминал, копирование команды, офлайн-проба политик | Меняется поведение |
| `data.js` | Словари RU/EN, правила пробы с regex и вердиктами, сценарий терминала, список харнессов | Меняются тексты и правила |
| `config.js` | Ссылка на GitHub, команда установки, `<title>` и описание | Меняются артефакты и адреса |
| `eva/` | Фигуры Evangelion для фона секций (PNG с прозрачностью, ~100 КБ каждая); подключаются в `index.html` классом `deco` | Меняется набор или расстановка фигур |

Тексты берутся из `data.js` по атрибуту `data-i18n`, ссылки из `config.js` по `data-link`. Чтобы поменять ссылку или число, разметку трогать не нужно.

`handoff/README.md` — исходная спецификация дизайна из Claude Design (структура, токены, поведение). По ней сайт и собран; при правках дизайна сверяйтесь с ней.

## Как проверить локально

Любой статический сервер из `site/`, например:

```bash
cd frontend/site && python3 -m http.server 8765
```

Открыть `http://localhost:8765`. ES-модули не работают с `file://`, сервер обязателен.

## Как деплоится

`cd service && make deploy` синхронизирует `frontend/site/` в `/opt/openmagi-site` на сервере и перезапускает стек. Caddy монтирует этот каталог как `/srv/site` и отдаёт статику для хостов из `AGENTGATE_SITE_HOSTS` серверного `.env` (сейчас `openmagi.ru www.openmagi.ru`). Сертификаты Caddy получает сам. Ни сборки, ни Node на сервере нет.

## Что ещё не подтверждено

Значения в `config.js`, взятые из хэндоффа как заглушки: ссылка на `github.com/agentgate`. Секция бенчмарка с сайта убрана до первого прогона.

## Однострочная установка

```
curl -fsSL https://openmagi.ru/install.sh | sh
curl -fsSL https://openmagi.ru/install.sh | sh -s -- --level high --only kilo
```

`site/install.sh` скачивает `openmagi-src.tar.gz`, **сверяет sha256** и только потом
распаковывает — архив с перехваченного соединения иначе исполнился бы от имени
запустившего. Репозиторий приватный, поэтому клонировать нечего: скрипт берёт
архив с того же хоста, что отдаёт сайт.

Архив и сумма **лежат в гите** рядом со скриптом. Это осознанный размен: 584 КБ
в истории на каждую пересборку против выкладки, которая молча уходит со старым
архивом. Второе уже случалось — установщик сверил sha256 прошлой версии, нашёл
валидным и поставил старый код, и ничто на всём пути не выглядело сломанным.

Пересобирать **перед коммитом**, если менялось что-то в `adapters/` или `service/`:

```
bash frontend/pack-install.sh
```

Контрольная сумма подтверждает, что архив цел, но никогда — что он актуален.
Единственное, что связывает архив с исходниками, — дисциплина этой пересборки.

Две вещи, которые скрипт делает не очевидно, и обе нужны:

- **`< /dev/tty` для мастера.** Под `curl … | sh` стандартный ввод скрипта — это
  труба, и мастер прочитал бы EOF, ничего не спросив. Терминал передаётся ему
  явно; там, где терминала нет (CI, контейнер), мастер остаётся неинтерактивным.
- **`bun` не ставится за пользователя.** Его установщик — такой же `curl … | sh`,
  и подцеплять один к другому втихую именно то, от чего наш продукт защищает.
  Без `bun` установка проходит, но бандлы плагина не собираются.
