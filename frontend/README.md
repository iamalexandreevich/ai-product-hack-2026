# frontend — сайт openmagi.ru

Направление 4. Лендинг OPENMAGI, который Caddy отдаёт на `openmagi.ru` и `www.openmagi.ru`. Бэкенд живёт отдельно на `api.openmagi.ru` (см. `docs/connect.md`), сайт к API не обращается.

## Что здесь лежит

- `site/` — то, что реально отдаётся с сервера. Сейчас это прототип из Claude Design как есть: `index.html` (переименованный `OPENMAGI.dc.html`) и его рантайм `support.js`. Страница компилируется в браузере: React, ReactDOM и Babel подгружаются с unpkg при каждом открытии, шрифты с Google Fonts. Для демо годится, для продакшена нет.
- `handoff/` — материалы дизайн-хэндоффа для пересборки: `README.md` со спецификацией страницы (структура, токены, поведение), `data.js` (словари RU/EN, правила офлайн-пробы, сценарий терминала) и `tokens.css`. Сайт их не использует, они для следующего шага.

## Как деплоится

`cd service && make deploy` синхронизирует `frontend/site/` в `/opt/openmagi-site` на сервере и перезапускает стек. Caddy монтирует этот каталог как `/srv/site` и отдаёт статику для хостов из `AGENTGATE_SITE_HOSTS` серверного `.env` (сейчас `openmagi.ru www.openmagi.ru`). Сертификаты Caddy получает сам. Ни сборки, ни Node на сервере нет.

## Следующий шаг

Пересобрать страницу в чистую статику по `handoff/README.md`: без Babel в браузере, с `data.js` как источником строк и правил. Деплой при этом не меняется: новая сборка кладётся в `site/`.

Открытые места из хэндоффа, которые нужно подтвердить: домен установочного скрипта `openmagi.dev`, ссылки на GitHub `github.com/agentgate`, значения метрик бенчмарка, пути хуков харнессов.
