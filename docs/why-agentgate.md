# Зачем AgentGate, если в Claude Code и Codex уже есть Auto Mode

Короткий ответ: Auto Mode это удобство внутри одного закрытого продукта. AgentGate это политика безопасности, которая живёт вне харнесса, одинакова для всех агентов в команде, имеет детерминированный слой до LLM и позволяет самому выбирать модель, где хранятся данные и как измерять качество. Для одиночного разработчика, который пользуется только Claude Code, встроенного режима достаточно. Ценность AgentGate растёт с числом харнессов, требованиями к политике и ограничениями по стоимости и приватности.

Ниже семь причин, факты взяты из `docs/artifacts/coding-agent-security-market-2026.html`.

## 1. Auto Mode есть только у закрытых вендоров

Claude Code (по умолчанию с 14 августа 2026), Cursor Auto-review и Codex Auto-review это закрытые реализации. В open source (Kilo Code, OpenCode, Cline, Roo Code, Pi, OpenHands) выбор по-прежнему бинарный: подтверждать каждый шаг или включить YOLO и отключить проверки. В Kilo auto mode только проектируется (issue #9138), в Kiro открыт запрос (#10364). Команда, которая использует хотя бы один открытый агент, сегодня либо страдает от approval fatigue, либо работает без защиты. AgentGate даёт auto mode любому харнессу через один хук.

## 2. Одна политика на все агенты, а не по файлу настроек на каждый

Разработчики в одной команде используют разные агенты, и у каждого свой формат: `settings.json` у Claude Code, `config.toml` и `requirements.toml` у Codex, `permissions.json` у Cursor, правила `{permission, pattern, action}` у Kilo. Политика расползается, её нельзя проверить или проревьюить целиком, при смене агента она теряется. В AgentGate политика одна, в YAML на стороне сервиса, в git, с историей изменений. Харнессы о ней не знают и передают только действие и запрос пользователя.

## 3. Детерминированный слой до LLM, который не читает текст

Auto Mode это LLM-классификатор. Anthropic сам пишет, что он не даёт гарантий безопасности, а жёсткая граница это OS-сэндбокс и egress-фильтр. На практике Rehberger обошёл Auto Mode Opus 5 с 60–80 % успешных инъекций через цепочку WebFetch → curl → ZIP. Классификатор, который видит отравленный контекст, по построению уязвим к тому, что в этом контексте написано.

Ступень 1 AgentGate текст не читает вообще. Она разбирает команду в AST и сверяет дерево с профилем: эксфильтрация секретов, деструктив вне workspace, `curl | sh`, запись в конфиги агента, `sudo`, force push. Эти правила не переопределяются ни пользователем, ни моделью, ни инструкцией из README. Это ровно тот контроль, «архитектурно неуязвимый к prompt injection», который требует кейс, и его нет ни в одном auto mode. В roadmap к этому добавляется provenance: аргументы, дословно скопированные из вывода инструментов, блокируются без участия LLM.

## 4. Свобода выбора модели, стоимости и периметра данных

У Claude Code классификатор это Sonnet 4.6, у Codex это отдельный ревьюер-агент, и оба тарифицируются токенами вендора. Пользователи Codex жаловались на расход токенов ревьюером ещё в августе 2026. Каждое действие агента вместе с запросом пользователя уходит к вендору.

В AgentGate модель это три строки конфигурации через OpenAI-совместимый API: облачная средняя модель, открытая модель на своём сервере или маленькая локальная на CPU. Для банка или компании с on-prem-требованиями это единственный способ получить auto mode, при котором ни команда, ни запрос пользователя не покидают периметр. Read-only команды и hard-deny вообще не доходят до модели, поэтому большинство решений стоят ноль токенов.

## 5. Каждое решение измеримо

Auto Mode не показывает, почему он разрешил действие, какая стадия сработала и сколько это стоило. Публичные цифры (FPR 0,4 %, FNR 17 %) получены на данных вендора и на его политике. Проверить их на своей задаче нельзя.

AgentGate пишет каждое решение в Postgres: действие, запрос пользователя, ступень, правило, модель, сырой ответ модели, latency по ступеням, хэш профиля. На этих данных считаются ASR, FP, Friction и Latency для конкретной политики и конкретной модели, а модель можно заменить и пересчитать. Это превращает безопасность агента из обещания вендора в метрику команды.

## 6. Тот же UX, что у Auto Mode, без потерь

Мы не делаем работу агента хуже. Deny-and-continue устроен как у Claude Code и Codex: отказ уходит агенту как результат инструмента с причиной и безопасной альтернативой, агент продолжает. Эскалация к человеку после 3 отказов подряд или 10 из последних 50, как в Codex. Read-only и правки внутри workspace проходят без модели за миллисекунды. Цель сервиса та же, что у Auto Mode: убрать человека из цикла подтверждений там, где он всё равно жмёт «да» в 97 % случаев.

## 7. Нет привязки к вендору

Политика в `settings.json` Claude Code не переносится в Codex, а правила Kilo не переносятся никуда. Смена агента означает настройку защиты заново. С AgentGate смена харнесса это смена адаптера, политика, лог и метрики остаются.

## Чего AgentGate не обещает

- Не заменяет сэндбокс. Изоляция исполнения остаётся у харнесса, мы её требуем, а не реализуем.
- Не даёт гарантии на серую зону: ступень 2 это LLM и она ошибается. Гарантия есть только на то, что закрывает ступень 1.
- В v1 не видит историю действий и выводы инструментов, поэтому многошаговые атаки без дословного копирования ловит только модель.
- Добавляет сетевой вызов на каждое действие серой зоны. Для read-only и hard-deny задержка в миллисекунды, для модели десятки или сотни миллисекунд в зависимости от выбранной.

## Когда AgentGate не нужен

Один разработчик, один Claude Code, нет требований к приватности и аудиту. Встроенный Auto Mode плюс `sandbox-runtime` закрывают эту ситуацию, и добавлять сервис незачем.
