# Выпуск API-ключей на развёрнутом сервере из локального Makefile

Дата: 7 сентября 2026. Статус: принято владельцем продукта («только оператору, вариант 1»).

## Проблема

`python -m agentgate keys create|list|revoke` существует с Task 11, но работает только там, где доступен Postgres — то есть внутри контейнера `gate` на сервере. Выпустить ключ для `api.openmagi.ru` сегодня значит вручную зайти по SSH, вспомнить `/opt/agentgate`, набрать `docker compose exec …` с обоими compose-файлами и скопировать ключ из вывода. Три шага, каждый из которых легко сделать неверно (забыть overlay, забыть `-T`, потерять ключ в скролле).

## Решение

Три цели в `service/Makefile`, рядом с `deploy`/`logs`/`ps`, которые запускают тот же CLI внутри контейнера `gate` по SSH:

```
make key LABEL=kilo-ci [EXPIRES=90d]   # печатает ключ один раз в stdout
make keys                              # таблица ключей без секретов
make key-revoke ID=<key_id>            # мягкий отзыв
```

Доверие доказывается тем же SSH-псевдонимом `$(DEPLOY_HOST)`, что и у `make deploy`: ни новых эндпоинтов, ни новых секретов, ни изменений в базе. Спека `api-keys.md` («Скрипт на сервере (минимум)») выбрана осознанно: получатель ключа — оператор с SSH. Формы «инвайт» и «регистрация» остаются в roadmap до появления запроса «ключ человеку без доступа к серверу».

## Детали

- Все три цели идут через `$(COMPOSE) exec -T gate uv run python -m agentgate keys …` в `$(DEPLOY_DIR)` — тот же путь, что и миграции в `deploy`, так что контейнер и окружение те же.
- `-T` обязателен: без TTY `ssh` не интерактивен и stdout ключа остаётся чистым для `pbcopy`/подстановки.
- `make key` без `LABEL` и `make key-revoke` без `ID` падают с сообщением до обращения к серверу.
- `LABEL` подставляется в одинарных кавычках; метка с одинарной кавычкой не поддерживается (ограничение описано в README).
- Ключ печатается только CLI внутри контейнера и только в stdout; Makefile не пишет его ни в `echo`, ни в файл.

## Тесты

`tests/test_makefile_keys.py`: `make -n` собирает командную строку без выполнения; проверяется, что `key` содержит `exec -T gate`, `keys create --label`, `--expires` только при `EXPIRES`, `key` без `LABEL` и `key-revoke` без `ID` завершаются ненулевым кодом с сообщением.

## Не делаем

Инвайты, эндпоинт выпуска, ротацию, копирование ключа в буфер обмена.
