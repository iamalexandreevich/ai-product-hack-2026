# Деплой v1.5 как общий эндпоинт для интеграции

Дата: 4 сентября 2026. Статус: утверждено владельцем продукта в этот день. Продолжение `deploy.md`; фактура — `docs/reports/deploy-handoff.md`.

## Цель

Команда (adapters, benchmark, внешние интеграторы) подключается к одному серверу по HTTPS с одним токеном и не поднимает сервис локально. `make deploy` выкатывает текущий `main`, а `/healthz` отвечает, какая ревизия развёрнута.

## Решения владельца, принятые 4 сентября

| Вопрос | Решение |
|---|---|
| Что разворачиваем | `main` как есть, включая v1.5 и изменённый `contracts/` (описания, документированный `422`, `model_raw_response` в ленте). Согласие трёх направлений считается полученным решением владельца |
| Чем авторизуются интеграторы | Один общий `AGENTGATE_TOKEN`. Ключи (`agk_…`) остаются доступны, но не раздаются в этой задаче |
| TLS | Домена нет и покупать не нужно: `109.172.95.51.sslip.io`. Caddy на сервере |
| Гигиена | Все четыре пункта: `git_sha` в `/healthz`, rsync по `.gitignore`, удалить лишний SSH-ключ, переименовать `TOKEN` в локальном `.env` |
| Запуск `make deploy` | Выполняется в рамках задачи после зелёных тестов |

## Что обнаружено на сервере 4 сентября

- `/healthz` и `/v1/decide` доступны снаружи, неавторизованный запрос даёт `401`. В логах есть внешний интегратор и успешные вызовы OpenRouter: ступень 2 работает.
- **Postgres опубликован на `0.0.0.0:5433`** с паролем `agentgate`, файрвол выключен. Подключение к порту с внешней машины проходит. Это закрывается в этом деплое.
- Порты 80 и 443 свободны.
- Код на сервере — v1 до рефакторинга; миграции `0001`, `0002` применены, то есть схема базы у v1.5 та же.

## 1. Сеть и TLS

**Имя.** `109.172.95.51.sslip.io` — публичный DNS, который любое имя `<ip>.sslip.io` резолвит в этот IP. Резолюция проверена. Имя хранится на сервере в `.env` как `AGENTGATE_PUBLIC_HOST`; в репозитории IP не появляется (правило Makefile).

**Caddy.** Файл `service/docker-compose.deploy.yml` — оверлей поверх `docker-compose.yml`, применяется только на сервере. Сервис `caddy` (образ `caddy:2`), порты `80:80`, `443:443`, том `caddydata` для сертификатов, `Caddyfile` из `service/deploy/Caddyfile`:

```
{$AGENTGATE_PUBLIC_HOST} {
    reverse_proxy gate:8400
}
```

Caddy сам получает сертификат Let's Encrypt по HTTP-01/TLS-ALPN-01 и продлевает его. Локальный `docker compose up` оверлей не использует и Caddy не поднимает.

**Риск sslip.io.** Домен не в Public Suffix List, поэтому недельный лимит Let's Encrypt (50 сертификатов на зарегистрированный домен) общий для всех пользователей sslip.io. Caddy при отказе LE автоматически пробует ZeroSSL. Если откажут оба, покупается любой домен, ставится A-запись на `109.172.95.51` и меняется `AGENTGATE_PUBLIC_HOST` в серверном `.env`. Ничего больше не меняется.

**Postgres.** В базовом `docker-compose.yml` публикация меняется на `127.0.0.1:5433:5432`. Локальные тесты и README продолжают ходить на `localhost:5433`; снаружи порт закрыт. Пароль не меняется: база больше не достижима извне, а смена пароля тянет за собой `AGENTGATE_DB_URL` и живые данные — отдельная задача, если понадобится.

**Порт 8400** остаётся опубликованным на `0.0.0.0` в этом деплое: через него уже работает внешний интегратор. Закрывается следующим деплоем (`127.0.0.1:8400:8400`), когда все перейдут на HTTPS. Записано в roadmap этой спеки.

**ufw не включается.** Docker публикует порты в обход ufw, реальный контроль — адрес привязки в compose.

## 2. Ревизия в `/healthz`

Цепочка: `make deploy` вычисляет `GIT_SHA=$(git rev-parse HEAD)` и передаёт его в окружение команды на сервере → `docker-compose.yml` пробрасывает `build.args.GIT_SHA: ${GIT_SHA:-}` → `Dockerfile` объявляет `ARG GIT_SHA` и кладёт `ENV AGENTGATE_GIT_SHA=$GIT_SHA` → `Settings.git_sha: str | None = None` → `Health.git_sha: str | None`.

Семантика: полный SHA коммита, из которого собран образ; `null`, если образ собран без аргумента (локальная сборка). Пустая строка из build-arg нормализуется в `null`.

Изменение контракта аддитивное: одно новое поле в ответе `GET /healthz`. `contracts/openapi.yaml` перегенерируется скриптом; `tests/test_contracts.py` подтверждает совпадение.

Тесты: `/healthz` отдаёт `git_sha` из настроек; отдаёт `null`, когда не задан; пустая строка → `null`.

## 3. Makefile

- Одна переменная `COMPOSE := docker compose -f docker-compose.yml -f docker-compose.deploy.yml`, все цели (`deploy`, `logs`, `ps`, `rollback`) идут через неё.
- rsync: `--filter=':- .gitignore'` вместо перечисления. Явными остаются два исключения с комментарием почему: `.env` (страховка: серверные секреты нельзя перезаписать, даже если `.gitignore` кто-то тронет) и `.previous_gate_image` (не в `.gitignore`, а `--delete` его снёс бы).
- `deploy` передаёт `GIT_SHA` в окружение серверной команды.
- После серверной проверки `/healthz` на `localhost:8400` добавляется проверка с машины оператора: `curl -fsS https://$PUBLIC_HOST/healthz`, где `PUBLIC_HOST` читается с сервера из `.env` через ssh. Так деплой подтверждает и TLS, и внешнюю доступность, а не только процесс внутри.
- `rollback` не меняется по смыслу; работает через `COMPOSE`.

## 4. Гигиена

- Сервер: из `/root/.ssh/authorized_keys` удаляется строка с комментарием `agentgate-deploy@…`. Локально удаляется пара `~/.ssh/agentgate_deploy*`. После удаления проверяется, что `ssh -o BatchMode=yes agentgate` по-прежнему проходит (алиас использует `id_ed25519_vpn`).
- Локальный `service/.env`: ключ `TOKEN` переименовывается в `AGENTGATE_TOKEN` через `sed -i` без вывода содержимого. Файл не читается и не коммитится.
- Серверный `/opt/agentgate/.env`: дописывается `AGENTGATE_PUBLIC_HOST=109.172.95.51.sslip.io`.
- `docker-compose.yml.bak` на сервере удалит сам `rsync --delete`: правка уже в репозитории.

## 6. Деплой и проверка

Порядок: тесты зелёные локально → коммит → `cd service && make deploy` → проверки:

1. `https://109.172.95.51.sslip.io/healthz` отдаёт `status: ok`, `db: true`, `git_sha` равен `git rev-parse HEAD`.
2. `POST /v1/decide` по HTTPS с токеном: `npm test` → `allow`, `curl … | sh` → `deny`.
3. `nc -z 109.172.95.51 5433` не проходит.
4. `http://109.172.95.51:8400/healthz` по-прежнему отвечает.
5. `make rollback` не запускается, но `.previous_gate_image` на сервере записан.

Если `/healthz` не поднялся за 30 секунд, деплой считается неуспешным; оператор смотрит `make logs` и решает про `make rollback`.

## Тестирование

- Юнит: `Health.git_sha` через настройки (три случая выше), схема `Health` в `openapi.yaml`.
- Конфигурация: `docker compose -f docker-compose.yml -f docker-compose.deploy.yml config` проходит локально с подставленными `AGENTGATE_TOKEN` и `AGENTGATE_PUBLIC_HOST`.
- rsync: `rsync -n` (dry run) перед реальным деплоем показывает, что `.env` и `.previous_gate_image` не трогаются, а кэши не уезжают.
- Приёмка: шесть проверок раздела 6 на живом сервере.

## Наследуемые ограничения

- Fail-closed относится к решениям сервиса; деплой, не прошедший health-check, считается неуспешным.
- Makefile не несёт IP, ключей и паролей: хост через алиас `~/.ssh/config`, публичное имя через серверный `.env`.
