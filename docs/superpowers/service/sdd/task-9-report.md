## Проверка примеров «Как добавить»

Все три примера прогнаны как код, а не написаны по памяти
(`scratchpad/check_examples.py`, в репозиторий не попадает):

```
example 1 (rule): hard-deny.kubectl-delete deny hard= True
example 2 (classifier): local-guard ask
example 3 (store): ok, restored and cached through a custom inner store
ALL THREE EXAMPLES OK
```

- Правило: класс из 8 строк, вставлен в `RuleChain` перед `STAGE1`, отдаёт hard-deny на
  `kubectl delete pod api-0` и молчит на `ls -la`.
- Классификатор: класс из 5 строк, подставлен в `Gate` через реестр; `decide` с `model="local-guard"`
  вернул `ask` с `model="local-guard"`. **Уточнение, найденное прогоном:** имя классификатора должно
  совпадать с тем, что харнесс шлёт в поле `model` (или с `models.default`), иначе `Gate._resolve`
  отвечает `api.unknown-model`. Первая версия примера этого не учитывала; в README написано верно.
- Хранилище: класс из 5 методов подставлен внутрь `PersistentSessionStateStore`, `restore()` и
  кэш работают через него.

Вывод: заявленное «один новый класс и одна строка в списке» подтверждено, а не заявлено.
