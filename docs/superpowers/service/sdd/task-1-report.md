## Finding 2 — `bind_port` crashes/misparses on realistic configs

Fixed in `service/agentgate/config.py`. Added a module-level `_split_bind(value: str) -> tuple[str, int]` helper and a pydantic `field_validator("bind")` (`_validate_bind`) that calls it at construction time. Rules implemented exactly as specified by the controller ruling:

- Requires `host:port` — empty host, missing `:`, or empty port segment all raise `ValueError` naming the offending value.
- Port must parse as `int` and lie in `1..65535`; otherwise raises.
- IPv6 host must be bracketed (`[::1]:8400`); a bracketed host has its brackets stripped for `bind_host`. A host containing `:` without brackets (e.g. bare `::1`, which `rpartition(":")` turns into host `"::"` + port `"1"`) is rejected because the leftover host still contains `:`.
- `bind_host` and `bind_port` now call `_split_bind(self.bind)` and are total (cannot raise) once construction has succeeded, since the field validator already guaranteed validity. Same names and return types (`str`, `int`) as before, per the ruling — Task 13's `uvicorn.run(host=settings.bind_host, port=settings.bind_port)` is unaffected.
- `bind_is_localhost` unchanged: membership of the bracket-stripped host in `_LOCALHOST = {"127.0.0.1", "localhost", "::1"}`. `[::1]:8400` now correctly reports `True`.
- Did not implement any of the explicitly out-of-scope items (case-insensitive host matching, `127.0.0.0/8` range matching, whitespace-only token rejection, resetting `get_settings`'s `lru_cache`).

Verified pydantic's `ValidationError` is a subclass of the built-in `ValueError` (confirmed via `ValidationError.__mro__` in the project's venv), so `pytest.raises(ValueError)` in the tests catches both the validator's own `ValueError` and pydantic-settings' wrapping `ValidationError` for a missing `db_url`.
