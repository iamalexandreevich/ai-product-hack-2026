Исследование рынка под хакатонный кейс «безопасность ИИ-кодинг-агентов»

Кто и как сегодня защищает кодинг-агентов: закрытые продукты, open source, бенчмарки и пробелы

Обзор механизмов разрешений, изоляции выполнения, защиты от prompt injection (внедрения вредоносных инструкций через контент) и slopsquatting (подмены галлюцинированных пакетов), с полным списком артефактов и ссылками. Точка отсчёта — Claude Code Auto Mode, цель — воспроизвести сопоставимый движок в Kilo Code.

Актуальность: 2 сентября 2026. Ссылки приведены только на реально найденные источники; там, где источник не подтверждён, это отмечено в оговорках.

Кратко

  • Рынок разделился на две модели контроля. Закрытые вендоры (Claude Code, Cursor, OpenAI Codex, GitHub Copilot) поставили LLM-классификатор («auto mode») поверх детерминированного OS-сэндбокса. В open source (Kilo Code, Cline, Roo Code, OpenHands) по-прежнему ручное подтверждение каждого шага либо бинарный YOLO-режим (полное отключение проверок). Сопоставимого auto-mode-движка в OSS пока нет, и именно этот пробел закрывает кейс.
  • Архитектурно неуязвимы к prompt injection только детерминированные контроли уровня ОС и сети: sandbox (@anthropic-ai/sandbox-runtime, Codex Seatbelt/Landlock, gVisor, Firecracker) и egress-фильтрация (ограничение исходящего трафика по allowlist доменов). LLM-классификаторы и гардрейлы остаются эвристикой: Anthropic сам подчёркивает, что auto mode не даёт гарантии безопасности, а заявленный Trajectory Labs нулевой ASR был опровергнут ручным обходом (Johann Rehberger, 60–80 % успешных инъекций).
  • Реалистичный план на хакатон: двухступенчатый reasoning-blind классификатор в Kilo Code (архитектура уже описана в issue #9138 / #10248 / #10249), обёртка агента в @anthropic-ai/sandbox-runtime как контроль, до которого инъекции не доходят, slopsquatting-хук на базе DepScope MCP и эвристик возраста/загрузок, бенчмарк с метриками ASR / Utility / FP / Friction / Latency на базе RedCode-Exec (bash) и CARE.

Ключевые выводы

  1. Claude Code Auto Mode стал режимом по умолчанию 14 августа 2026 (анонс Anthropic — 7 августа 2026). Классификатор на Claude Sonnet 4.6 блокирует необратимые, разрушительные и направленные наружу действия. В слепом исследовании на 1 053 платных тестировщиках люди заметили подброшенную опасную команду в 13,6 % случаев, классификатор — в 89 %; при этом доля пойманных человеком команд падала с ~17 % до ~5 % после 50+ промптов в сессии.
  2. Approval fatigue (усталость от подтверждений) подтверждена производственными данными. По данным Anthropic, пользователи одобряют 97 % всех запросов на разрешение, включая 86 % запросов с опасными командами; сессии с ручным одобрением давали серьёзный непреднамеренный вред в 6,3 % случаев против 2,4 % у auto mode.
  3. Auto mode как защита от prompt injection переоценён. Trajectory Labs (по заказу Anthropic, 72 сценария × 10 прогонов): 0 из 720 попыток против Claude в auto mode, 5,83 % у GPT-5.6 на Codex Auto-review, 19,03 % у Codex Full Access. Однако Johann Rehberger (Embrace The Red, 26 августа 2026) обошёл Opus 5 Auto Mode с 60–80 % ASR через простой запрос на суммаризацию URL: цепочка WebFetch → HTTP 415 → откат на curl → ZIP с вредоносным struct.py, перекрывающим модуль стандартной библиотеки. Anthropic признаёт: реальная граница безопасности — OS-изоляция и egress-контроль.
  4. В open source auto-mode-движка нет, но Kilo Code его активно проектирует: issue #9138 (детальный дизайн двухступенчатого reasoning-blind классификатора), #10248 (rollout), #10249 (runtime foundation). Аналогичный запрос открыт в Kiro (#10364).
  5. TRAP (arXiv:2512.23128, Korgul et al., декабрь 2025, ICLR 2026) — источник цифр 13 % (GPT-5) и 43 % (DeepSeek-R1). Важно: бенчмарк рассчитан на веб-агентов, не на кодинг-агентов. Средний ASR 25 % по шести frontier-моделям, 3 780 прогонов, 948 успешных атак.
  6. Slopsquatting подтверждён академически: 19,7 % пакетов, предлагаемых LLM, — галлюцинации (Spracklen et al., USENIX Security 2025, Best Paper). Защита «внутри агента до установки, против zero-day» через сравнение имён невозможна (имена галлюцинаций новые). Работают эвристики (возраст пакета, загрузки, наличие репозитория), проверка существования в реальном времени (DepScope MCP) и release-age cooldown (минимальный возраст релиза перед установкой).

1. Механизмы разрешений и auto mode в кодинг-агентах

Состояние рынка. Закрытые вендоры прошли путь от бинарного «ask / bypass» к трёхуровневой модели: allowlist → сэндбокс → LLM-классификатор. Claude Code (14 августа 2026), Cursor Auto-review (v3.6, 29 мая 2026) и Codex Auto-review сходятся к одной архитектуре. Open source задержался на ручном подтверждении или YOLO; Kilo Code первым проектирует полноценный аналог.

Закрытые и коммерческие

  • Claude Code Auto Modeпродукт
    Классификатор Sonnet 4.6. Многоуровневый short-circuit: Tier 1 — read-only allowlist (чтение, grep, glob, планы), Tier 2 — правки внутри проекта без вызова классификатора, Tier 3 — shell, webfetch, MCP, субагенты, выход за пределы проекта. Reasoning-blind вход: классификатор видит только сообщения пользователя и «голые» tool-call payload, без рассуждений модели и вывода инструментов. Deny-and-continue (3 отказа подряд или 20 всего → эскалация к человеку), hard denies для эксфильтрации данных. Двухстадийная схема: Stage 1 — single-token yes/no (8,5 % FPR, 6,6 % FNR), Stage 2 — chain-of-thought только на флагах (0,4 % FPR, 17 % FNR end-to-end). Настройки через settings.json (defaultMode, disableAutoMode, --dangerously-skip-permissions).
    Анонс (7 авг 2026)Документация по конфигурацииEngineering writeup (25 марта 2026)Обзор Help Net SecurityЧто блокирует auto mode
  • Cursor Run Modes / Auto-reviewпродукт
    Режимы Allowlist / Auto-review / Run Everything; sandbox.json с egress-allowlist (только sandbox.json / плюс defaults / всё разрешено); permissions.json (allow_instructions / block_instructions); классификатор-субагент. Вендор прямо называет это best-effort гардрейлом, а не жёсткой границей безопасности.
    Документация Run ModesCursor Hardening Guide
  • OpenAI Codex CLIпродуктOSS-ядро

2. Sandboxing и изоляция выполнения

Состояние. Единственный класс детерминированных контролей, до которых prompt injection не доходит. Anthropic и OpenAI сошлись на OS-примитивах для CLI (Seatbelt, bubblewrap, Landlock) и gVisor / microVM для облака. Граница виртуальной машины и есть граница безопасности; всё остальное — defense-in-depth (эшелонированная защита).
  • @anthropic-ai/sandbox-runtime (srt)OSS-репозиторийдетерминированный
    bubblewrap (Linux / WSL2) или Seatbelt через sandbox-exec (macOS) плюс socat-релей на egress-прокси с allowlist доменов. Оборачивает весь процесс Claude Code (все tools, hooks, MCP-серверы), а не только Bash.
    Выбор sandbox-средыДокументация Sandboxing

3. Защита от prompt injection в источниках инструкций

Состояние. Два лагеря. Первый — детерминированные архитектурные паттерны (CaMeL, design patterns, information-flow control), которые доказуемо ограничивают ущерб. Второй — эвристические гардрейлы (LlamaFirewall, Lakera, guard-модели), которые обходятся. Инциденты 2025–2026 показали, что конфиг-файлы агентов (.cursorrules, CLAUDE.md, SKILL.md, описания MCP-инструментов) надо трактовать как исполняемый код.

4. Защита от slopsquatting и вредоносных зависимостей

Состояние. Требование кейса — защита внутри агента до установки, включая zero-day. Сравнение с известными именами бесполезно: галлюцинированные имена новые. Работают четыре приёма: проверка существования и репутации в реальном времени (DepScope MCP check_package), эвристики (возраст пакета, число загрузок, наличие репозитория, отсутствие пакета на момент запроса, схожесть с популярным), release-age cooldown (минимальный возраст релиза) и отключение lifecycle-скриптов при установке.

    Материал кейса. 8,5M+ пакетов, 19 экосистем, 22 MCP-инструмента (check_package, package_exists, find_alternatives, check_typosquat, check_malicious, scan_project), бесплатно и без авторизации. Собственный LLM Hallucination Benchmark: базовая доля установки галлюцинированных пакетов — 87 %.

8. Kilo Code: что есть и что потребуется

Архитектура. Форк Roo Code / Cline; CLI-часть основана на sst/opencode (packages/opencode/). Репозиторий Kilo-Org/kilocode — 26,9k звёзд, 3,1k форков.

Текущие permission-механизмы:

  • packages/opencode/src/permission/index.ts — rule-based {permission, pattern, action}, функция Permission.ask (строки ~190–239); LLM-оценки нет.
  • packages/opencode/src/kilocode/permission/routes.ts — POST /permission/allow-everything: wildcard-одобрение без гардрейлов.
  • packages/opencode/src/kilocode/permission/config-paths.ts — принудительный ask для .kilo/, .opencode/, AGENTS.md.
  • TUI auto-approve (src/kilocode/cli/cmd/tui/app.tsx), VS Code AutoApproveTab.tsx (статическая матрица allow / ask / deny), .kilocodeignore / .rooignore.
  • Legacy «AI Gatekeeper» (~388 строк в kilocode-legacy) — LLM-оценка при YOLO, но с одобрением при ошибке (approve-on-error), что небезопасно; при миграции yoloGatekeeperApiConfigId отбрасывается.

Что нужно для auto mode (по issue #9138): хук в Permission.ask; двухступенчатый reasoning-blind классификатор (Stage 1 — single-token на быстрой модели, Stage 2 — chain-of-thought); fail-closed с откатом в ask; deny-and-continue со счётчиками 3 подряд / 20 всего; tiered short-circuit (allowlist безопасных инструментов и правки внутри проекта минуют классификатор); сброс широких allow-правил (bash:*, python:*, npm run *) при входе в режим; конфиг permission.classifier с тремя prose-слотами (environment / allow / soft_deny); на втором этапе — probe на prompt injection в выводе инструментов. Системы hooks уровня Claude Code нет — её тоже придётся вводить.

Известные реализации auto mode: Claude Code, Codex Auto-review, White Circle

Три реализации решают одну задачу — убрать человека из цикла подтверждений, не расширяя фактических прав агента, — но делают это в разных точках стека. Claude Code и Codex встраивают LLM-«ревьюера» внутрь агента и опираются на OS-сэндбокс как на жёсткую границу; White Circle выносит контроль во внешний API-слой поверх любого агента (так его использует Lovable). Ниже — сравнение по тому, что известно из официальной документации и публичных исследований.

У White Circle — идею разделения ролей: политика описывается заказчиком в prose, а «Test → Protect» замыкает бенчмарк на генерацию правил, что напрямую ложится на этапы 4 и 6 кейса. Общая для всех трёх черта, которую нельзя терять: LLM-ревьюер никогда не расширяет права агента; жёсткая граница остаётся за сэндбоксом.

Детерминированные контроли против эвристических гардрейлов

Архитектурно неуязвимы к prompt injection

  • OS-сэндбокс: @anthropic-ai/sandbox-runtime (bubblewrap / Seatbelt), Codex Seatbelt / Landlock / seccomp, gVisor, Firecracker / microVM, nsjail.
  • Egress-фильтрация (allowlist доменов на прокси) — блокирует эксфильтрацию даже при захвате агента.
  • Information-flow control и capability-паттерны: CaMeL, FIDES, Progent, type-directed privilege separation, паттерны Action-Selector и Dual LLM.
  • Supply chain: release-age cooldown, hash-pinning описаний MCP-инструментов, отключение lifecycle-скриптов.

Эвристики (best-effort, обходятся)

  • LLM-классификаторы: Claude auto mode, Cursor Auto-review, Codex Auto-review, OpenHands security analyzer, Kilo #9138.
  • Guard-модели: PromptGuard 2, Lakera Guard, Rebuff, LLM Guard, NeMo Guardrails.
  • Денайлисты команд и pattern-scan (Cursor — CVE-2026-22708 показал обход через builtins).

Вывод для кейса. Требование «хотя бы один контроль архитектурно неуязвим к prompt injection» выполняется только детерминированным контролем: sandbox плюс egress-фильтр. Классификатор auto mode решает задачу удобства и снижения approval fatigue; гарантий безопасности он не даёт.

Пробелы на рынке и план на хакатон

Пробелы

  1. Нет OSS-аналога auto mode с fail-closed. Legacy-gatekeeper Kilo одобрял при ошибке; ни у одного открытого агента нет двухступенчатого reasoning-blind классификатора. Главный слот для PR в Kilo Code.
  2. Нет slopsquatting-контроля внутри агента до установки, устойчивого к zero-day. Существующие инструменты (Socket, GuardDog) — сканеры постфактум; нужен pre-install-хук, комбинирующий DepScope MCP с эвристиками (возраст < 7 дней, загрузки, наличие репозитория, схожесть имён) и fail-closed при 404.
  3. Нет стандартного бенчмарка dangerous-bash для кодинг-CLI с полным набором ASR / Utility / FP / Friction / Latency. RedCode-Exec (bash) и CARE дают основу, метрики Friction и Latency придётся добавить.
  4. Sandbox не интегрирован в open-source-агенты по умолчанию. Обёртка Kilo в @anthropic-ai/sandbox-runtime даёт контроль, до которого инъекции не доходят, «из коробки».

Что реально сделать за хакатон и подать в PR

  • Ядро: двухступенчатый reasoning-blind классификатор по #9138 (Stage 1 — single-token на быстрой модели, Stage 2 — chain-of-thought только на блоках), fail-closed, deny-and-continue со счётчиками 3/20, tiered short-circuit, сброс широких allow-правил. Ориентир по порогам: end-to-end FPR < 1 % при FNR < 20 % (уровень Claude Code).
  • Контроль, неуязвимый к инъекциям: интеграция @anthropic-ai/sandbox-runtime плюс egress-allowlist — закрывает обязательное требование кейса.
  • Slopsquatting-модуль: хук перед npm / pip install → DepScope MCP check_package + эвристики + release-age; fail-closed.
  • Бенчмарк: ASR / Utility / FP / Friction / Latency на RedCode-Exec (bash) + CARE + собственные кейсы (slopsquatting, инъекции в SKILL.md / README / MCP-описания, многошаговые атаки).
  • Продолжение после блокировки: deny-and-continue как tool-error с причиной — агент ищет безопасный путь, а не останавливается.
  • Allow / deny / ask-листы для команд и директорий плюс инструментирование approval fatigue (лог того, как часто люди пропускают опасные команды) — дополнительные баллы.

Поэтапный план

  1. Этап 1 — первые часыЗафиксировать архитектуру классификатора по #9138; поднять OS-sandbox (@anthropic-ai/sandbox-runtime) вокруг Kilo как отдельный, сразу демонстрируемый детерминированный контроль. Критерий перехода: sandbox блокирует запись вне workspace и egress вне allowlist.
  2. Этап 2 — серединаРеализовать Stage 1 классификатора (single-token, fail-closed, deny-and-continue) и tiered short-circuit; подключить slopsquatting-хук (DepScope MCP + release-age). Критерий: классификатор ловит ≥ 80 % опасных bash-команд из RedCode-Exec при FPR < 5 %.
  3. Этап 3 — финалДобавить Stage 2 (chain-of-thought), собрать бенчмарк с ASR / Utility / FP / Friction / Latency, залогировать метрику approval fatigue, оформить PR. Порог сдачи: end-to-end FPR < 1 %, FNR < 20 %, хотя бы один детерминированный контроль (sandbox / egress) в демо.

Что меняет план. Если классификатор даёт FPR > 5 % (много ложных блокировок) — переключиться на консервативный soft_deny-список и опору на sandbox. Если DepScope API нестабилен — откат на локальные эвристики плюс поле time.created из npm registry.

Оговорки и ограничения

  • Ряд цифр — вендорские и оспорены. Trajectory Labs 0,00 % ASR опровергнут независимо (Rehberger, 60–80 % ASR на Opus 5 Auto Mode). Доля пропусков классификатора 7 % измерена на синтетическом adversarial-наборе и не равна доле на реальном трафике.
  • Модели (Fable 5, Opus 5, Sonnet 5, GPT-5.6) и версии — по состоянию на сентябрь 2026; auto mode по умолчанию требует Claude Code v2.1.228+ (Windows v2.1.233+).
  • В статье о галлюцинациях пакетов есть две авторские формулировки (arXiv abstract 5,2 % / 21,7 % против ;login ~5 % / ~21 %; общая доля 19,7 %); в отчёте приведены цифры из abstract.
  • Цифра «93 % одобрений» из issue #9138 расходится с «97 %» из итогового анонса Anthropic — использована более поздняя.
  • DepScope Hallucinations Dataset — новый и малоизвестный проект (0 звёзд); проверьте актуальность API перед интеграцией.
  • Часть arXiv-идентификаторов 2026 года (CARE 2607.21642, SABER 2606.01317, MCP-SafetyBench 2512.15163) встречалась преимущественно как цитаты и препринты — проверьте первоисточники перед публикацией.
  • TRAP измеряет веб-агентов; прямой перенос 13 % / 43 % на кодинг-CLI некорректен без оговорки.
  • White Circle — внешний control layer общего назначения, а не auto mode внутри кодинг-агента; устройство его guard-моделей, состав контекста и метрики FP/FNR на задачах разработки публично не раскрыты, поэтому соответствующие ячейки таблицы заполнены по маркетинговым материалам и кейсу Lovable.
