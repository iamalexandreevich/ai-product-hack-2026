логах только "Сессия не найдена".

datetime.now() внутри цикла, и _meta не чистится никогда - TTL только фильтрует
чтение.

не обновляет operator_id и dialog_id - ровно те колонки, по которым идёт чтение.
Сценарий: первый запрос диалога пришёл без operator_info -> строка создана с
operator_id=''. Второй запрос уже несёт operator_id='op-1', SELECT по
(dialog_id, operator_id) эту строку не находит, создаётся новая Session с тем же
id=work_id, INSERT попадает в ON CONFLICT и перезаписывает context, оставляя
operator_id='' навсегда. Дальше каждый ход стартует с нуля, а накопленный контекст
затирается.

epk_id_ul не использует ни одна из четырёх реализаций, dialog_id / operator_id
игнорируют две из четырёх - докстринг на 44-46 это прямо признаёт.
Здесь не другой контракт, а другой КЛЮЧ СЕССИИ: у копилота это
(dialog_id, operator_id), а не workId. Если считать ключ в create_executor -
единственном месте, которое знает про поверхность - и передавать его как обычный
session_id, то:
  - базовые сигнатуры остаются как в agentsamo;
  - InMemoryVoiceCopilotSessionStorage исчезает целиком;
  - в таблице появляется PRIMARY KEY (dialog_id, operator_id), и вместе с ним
    пропадает ORDER BY ... LIMIT 1;
  - выбор хранилища схлопывается до двух веток.
Остаётся единственное настоящее отличие - TTL, и его хватает одного WHERE.
