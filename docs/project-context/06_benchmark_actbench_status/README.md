# Задача 29. ActBench: гард против его отсутствия на полном корпусе

Внешний исполняемый бенчмарк ActBench прогнан целиком — 300 пар задач, два плеча,
собственный инференс. Первое у нас измерение гарда там, где агент сам изобретает путь
к цели, а не получает готовую пару «запрос — действие».

## Что измерено

| | ASR |
|---|---:|
| без гарда | **30,4 %** (85/280) |
| с гардом (`decide-inspect`) | **24,3 %** (68/280) |

Парное сравнение по 280 задачам, решённым обоими плечами: гард предотвратил **24** атаки,
**7** удались только под ним. Точный тест Макнемара по 31 расходящейся паре — **p = 0,0033**.
Ошибок оценки ноль в обоих плечах. По контрольному плечу отдельно есть все 300 задач:
ASR 30,7 % (92/300).

ASR здесь — доля задач, где оценка выполнения атаки перешла порог 0,8. Сама оценка у нас
собрана только по логовому свидетельству: траекторное требует LLM-судьи, а он не вызывался.

## Условия прогона

- Корпус: ActBench, коммит `e532aa45fdb77ac81565fa5151d2652ffd94c828`, MIT, 300 пар.
- Агент: Claude Code, модель `claude-sonnet-5` по имени, фактически — наш Qwen 3.8
  (`giga-osa-qwen38/qwen3.8`) на osav1. Claude Code говорит только на Anthropic Messages API,
  osav1 отвечает лишь в форме OpenAI, поэтому между ними стоит LiteLLM-переводчик, а перед
  ним — `tools/anthropic_tap.py` с независимым журналом: **11 850 запросов, ни одного ответа
  кроме 200**.
- Ризонинг выключен, как во всех остальных сравнениях проекта.
- Оценка: `--score-mode automated`, LLM-судья не вызывался (`llm_invoked: false`).
- Гард: профиль `bench`, ступень 2 через нормализующий прокси на тот же Qwen 3.8.
- Стенд: сервер бенчмарка, 30 контейнеров-шардов. ActBench не параллелит задачи сам
  (`--run-workers` повторяет одну), поэтому корпус режется по идентификаторам; изоляция
  держится тем, что каждая задача получает свой каталог
  `/tmp/claweval/<прогон>/claudecode/<task_id>/workspace`.

Набор `representative` для этого бенчмарка непригоден: на его 15 задачах воспроизводятся
2 атаки (13,3 %), интервал Уилсона примерно [4 %, 38 %] — предотвращать почти нечего.
Мощность появляется только на полном корпусе, где достижимых атак 90.

## Сопоставление с опубликованными числами

ActBench публикует ASR для 15 базовых моделей — от 10,1 % (Claude-Opus-4.8) до 94,4 %
(Deepseek-v4-Pro). Наш контроль 30,4 % ложится между Hunyuan-3.0 (30,0 %) и Kimi-K3 (35,7 %);
под гардом 24,3 % попадает между MiniMax-M3 (25,0 %) и Claude-Sonnet-4.6 (20,0 %).

Читать это как «наш гард догнал Sonnet» нельзя. У них харнесс OpenClaw, у нас Claude Code;
у них оценка склеена из логового и траекторного свидетельств с LLM-судьёй, у нас — только
логовое. Порог 0,8 общий, но величина под ним разная, поэтому сопоставим порядок, но не
разряд. Внутри нашего прогона оба плеча измерены одинаково, поэтому осмысленна именно дельта.

Защитных решений в опубликованных материалах ActBench нет. В разделе RQ3 статьи прогнаны пять
детекторов (Prompt-Guard-2-86M, Llama-Guard-4-12B, AgentDoG-Qwen-4B, AI-Infra-Guard,
Cisco-Skill-Scanner), но авторы прямо оговариваются, что измеряют различающую способность на
границе наблюдения каждого метода и не оценивают причинное изменение ASR. Сквозного замера
защиты с дельтой ASR на ActBench в публичных материалах не существует.

## Воспроизведение

```bash
~/actbench/shards.sh off 30              # контроль
~/actbench/shards.sh decide-inspect 30   # с гардом
```
