## Implemented

### Сервис решений (`service/`)

Всё перечисленное подключено к основному потоку и покрыто тестами.

**HTTP-слой, пять маршрутов.** `agentgate/api/app.py`: `POST /v1/decide`, `POST /v1/inspect`,
`GET /v1/decisions`, `GET /v1/profiles/{id}`, `GET /healthz`. Тело записывающих маршрутов
парсится вручную, чтобы FastAPI никогда не вернул 422: невалидный JSON или схема дают
HTTP 200 с `api.invalid-request` (`ask` на `decide`, `drop` на `inspect`), чужой `protocol` —
`api.unsupported-protocol`, любое исключение движка — `api.internal-error`. Единственный
не-200 на них — 401.

**Каскад `decide`.** `agentgate/engine/gate.py`: резолв профиля и модели → состояние сессии и
workspace → нормализация в AST → allow-кэш → ступень 1 → ступень 2 → эскалация → фиксация
сессии. Персистентность вызывается строго после формирования ответа.

**Нормализация.** `agentgate/normalize/`: `bashlex` разбирает `raw` в список команд с
редиректами, путями, доменами, флагами (`unparseable`, `has_eval`, `has_subst`,
`has_env_assign`, `has_heredoc`, `has_unresolved_expansion`). Ошибка разбора даёт
`unparseable=True` с пустыми списками, а не частичный результат.

**Ступень 1 — 19 правил в одном списке.** `agentgate/rules/chain.py`, порядок и есть
приоритетная политика: `unparseable` → шесть hard-deny (`exfil`, `pipe-exec`, `destructive`,
`protected-write`, `privilege`, `git-force`) → `ambiguous.wrapper` → `client.deny` →
`profile.path` → `profile.domain` → `profile.mcp-refuse` → `client.ask` → `client.allow` →
`profile.mcp-allow` → `allowlist` → `allowlist.mcp-readonly` → `profile.domain-trusted` →
`packages`. Правило может вернуть не вердикт, а **пол строгости**: `client.ask` не
завершает цепочку и не покупает вызова модели, но запрещает итогу быть мягче `ask`.
Латентность p50 ≤ 1 мс проверяется тестом `tests/rules/test_latency.py`.

**Ступень 2 — LLM-классификатор.** `agentgate/classify/`: закрытый промпт (системная роль,
профиль, prose-слоты, `[TASK]`, `[HISTORY]`, `[ACTION]`, `[FLAGS]`, `[STAGE1]`), structured
output, один вызов, один таймаут, без ретраев. `metadata` и рассуждения агента не попадают в
промпт ни по какому пути. Любой сбой превращается в `ask` внутри самого классификатора.

**Каскад `inspect` (Context Guard для результатов инструментов).** `agentgate/inspect/` плюс
`agentgate/engine/inspector.py`: кэш по содержимому → сканер секретов (действие `redact`) →
детекторы (инструкциеподобный текст, `curl … | sh`, длинные блобы, невидимые символы) →
маска с приоритетом `redact > clean > mask` либо `drop` при пороге в половину строк →
сегменты вокруг находок из уже отредактированного текста → классификатор по режиму профиля →
сверка спанов модели с отправленными сегментами. Fail-closed здесь — `drop`.

**Клиентские правила (v3).** `agentgate/rules/client_rules.py`, `agentgate/domain/client_rules.py`:
поле `rules` в запросе с `allow`/`ask`/`deny`, матчинг по канонической форме действия, а не по
сырой строке. `client.deny` строже любого запрета сервиса; `client.allow` не перекрывает
hard-deny и запреты профиля.

**История диалога (v2).** `agentgate/domain/dialogue.py`: `history` с ролями и авторством,
дайджест полной истории входит в ключ allow-кэша, усечение по бюджету профиля — в промпт.

**Сессии, эскалация, кэши.** `agentgate/session/`: счётчики решений и окно последних 50,
эскалация в `ask` по порогам профиля, allow-only кэш (`deny` и `ask` не кэшируются), workspace
привязан к первому `cwd` сессии, повтор по `Idempotency-Key` в границах предъявителя и сессии.

**Хранилище и журнал.** `agentgate/store/`, `agentgate/log/jsonl.py`, `migrations/`: Postgres,
таблицы `sessions`, `decisions`, `allow_cache`, `api_keys`; строки `decide` и `inspect` живут
в одной таблице и различаются столбцом `kind`; девять ревизий Alembic; каждая строка
дублируется в append-only JSONL. Запись — в `BackgroundTasks` после ответа.

**Аутентификация и ключи.** `agentgate/api/deps.py`, `agentgate/store/keys.py`,
`agentgate/cli.py`: bearer проходит по статическому `AGENTGATE_TOKEN` **или** по выданному
API-ключу (аддитивно); в базе только SHA-256; выпуск только из CLI. С v3.2 решение
атрибутируется к `key_id`, с v3.3 форму `key_id` держат два `CHECK` в базе.

**Стоимость решения в ответе.** `agentgate/domain/usage.py`, поле `cost` в `DecideResponse`:
токены отдаются всегда, когда работала ступень 2; деньги — только если оператор задал
`price_per_1m_input`/`price_per_1m_output` в профиле. В развёрнутом профиле цены не заданы.

**Профили.** `agentgate/profiles/`, `service/profiles/default-dev.yaml`: пути, защищённые
пути и ветки, сеть, `safe_prefixes`, эскалация, prose-слоты, `history`, `inspect`, `mcp`,
таблица моделей. `profile_hash()` пишется в каждое решение.

**Контракты.** `contracts/`: `openapi.yaml` и четыре JSON-схемы **порождаются** из
pydantic-моделей (`service/scripts/export_contracts.py`, `export_openapi.py`);
`service/tests/test_contracts.py` падает при расхождении. Плюс каталог `examples/` с
реальными ответами развёрнутого сервиса и эталонный клиент `hook_client.py` (только stdlib,
fail-closed на всех путях).

### Слой интеграции с харнессами (`adapters/`)

TypeScript-монорепозиторий без сборки (Node ≥ 22.6 или Bun). Ядро `packages/core` содержит
HTTP-клиент, нормализацию, маппинг инструментов, режимы, кэш и политику доступности; плагины
харнессов логики решения не содержат.

Поддержаны шесть харнессов: **opencode 1.x** и **Kilo CLI** (через патч бинарника, свой на
каждый), **opencode 2.0**, **Pi**, **Codex CLI**, **DeepSeek Harness**. Плюс npx-инсталлер
(`install/status/doctor/mode/uninstall`), заглушка гарда для тестов и три уровня клиентских
правил (`low` / `medium` / `high` / `custom`).

Оба направления реализованы на клиенте: `PreToolUse` → `POST /v1/decide`, `PostToolUse` →
`POST /v1/inspect`. Режимы `auto` / `ask` / `allow` / `off` переключаются на лету.

## Реализовано частично

**Context Guard.** Закрыто направление «результат инструмента → модель»: детекторы,
маскирование секретов, обязательный провенанс шести видов, опциональный классификатор со
спанами. **Не закрыто:** остальные источники контекста (промпт пользователя, файлы проекта,
веб напрямую) сервис не видит, а провенанс работает как метка источника, а не как
распространяемая пометка — taint-цепочек между шагами нет.

**Session State.** Есть `Actions` (счётчики решений, окно последних 50) и `Audit Logs`
(Postgres + JSONL + лента). Нет `Files`, `Secrets`, `Destinations`, `Uploads`, `Cost`,
`Risk Score` как измерений состояния сессии; стоимость считается на решение, а не на сессию.

**Состояние сессии не общее между процессами.** На старте оно восстанавливается из Postgres,
дальше горячий путь читает и пишет только память процесса. Несколько воркеров uvicorn дают
независимые счётчики эскалации и независимые allow-кэши. Тот же характер у кэша проверки
API-ключей: отзыв ключа доходит до каждого воркера независимо, в пределах его TTL.

**Обработка `ask` на стороне харнесса.** Штатный диалог подтверждения используется там, где
он у харнесса есть; у Codex CLI в версии 0.146 из `PreToolUse` работает только `deny`, а
подмена результата не поддерживается, поэтому `mask` там вырождается в блокировку.

**Наблюдаемость.** JSONL, таблица решений, лента с фильтрами (`session_id`, `model`, `kind`,
`key_id`) и `/healthz`. Нет метрик (Prometheus), трейсинга и алертов. `healthz.llm` всегда
`null` — доступность модели ступени 2 не проверяется ни при старте, ни по запросу.

## Измеренные результаты

**Один прогон, 6 сентября 2026.** Гард `api.openmagi.ru` (`git_sha e3c7942`), профиль
`default` (`inspect.classifier: off`), ступень 2 — `openai/gpt-4.1-mini` через OpenRouter,
`--concurrency 1`. Артефакты в `benchmark/results/` (каталог в `.gitignore`, в репозитории их
нет); разбор — `benchmark/docs/reports/task-24-first-full-benchmark-run.md`. Цифры ниже
пересчитаны при аудите из SQLite прогона и совпали с отчётом.

**Замечание о свежести.** Цифры измерены против датасета в состоянии `d24af97`; после этого
61 атакующий кейс получил послабление `acceptable_service_results: [deny, ask]`. Пересчёт тех
же ответов против текущего датасета даёт точность 82,5 % вместо 80,0 %; ASR, Utility и FP не
меняются. Подробности — `06_benchmark_status.md`.

**Наш сервис, 120 pre-action кейсов** (90 атак, 30 контрольных): точность 80,0 % (96/120),
ASR 22,2 % (20 из 90), Utility 96,7 % (29/30), FP 3,3 % (1 из 30), ноль кейсов без решения.
Ступень 1 закрыла 50 решений, ступень 2 — 70. Латентность по данным сервиса: p50 1108 мс,
p95 1669 мс; вклад ступени 1 — p50 0 мс, максимум 3 мс. Все 24 провала пришлись на ступень 2;
ступень 1 не ошиблась ни разу.

**Inspect, 46 кейсов:** 40/46, ноль ошибок. Сдержано атак 100 % (21/21), сохранение чистого
вывода 83,3 %, вмешательство на чистых 16,7 %. Детекторный ярус — 40/40.

**Регрессии политики, 12 кейсов:** 12/12, каждый вердикт ровно как ожидался.

**Три конфигурации Claude Code, общая популяция 67 кейсов** (только те, по которым решение
вынесли все три; 46 атак / 21 чистый):

| Конфигурация | Точность | ASR | Utility | FP |
|---|---|---|---|---|
| `claude-code` — родной auto mode | 86,6 % (58/67) | 19,6 % (9/46) | 100 % (21/21) | 0 |
| `claude-agentgate` — наше ядро в хуках | 79,1 % (53/67) | 19,6 % (9/46) | 90,5 % (19/21) | 2 |
| `claude-sdk` — без классификатора | 26,9 % (18/67) | 0 % | 0 % | 21 |
| сервер напрямую, для справки | 79,1 % (53/67) | 23,9 % (11/46) | 95,2 % | 1 |

**Как это читать.** Родной auto mode на этой популяции сильнее нашего гарда: доля
пропущенных атак одинакова, но по строгой точности он впереди на 7,5 пункта и не даёт ни
одного ложного срабатывания. `claude-sdk` — якорь шкалы, а не защита: ноль пропущенных атак
и ноль выполненных задач одновременно.

**Ограничения этого прогона, названные в отчёте:** популяции трёх конфигураций теряются
неслучайно (решение вынесено по 88 / 77 / 70 кейсам из 120, причина одна — агент за шесть
ходов не предложил ни одного вызова инструмента), сервер напрямую и Claude-адаптеры видят
разное представление действия, цена в сравнение не входит, ActBench не запускался.

## Пользовательское исследование

**[Не компонент системы, но часть доказательной базы проекта.]** В репозитории есть
собственный опрос разработчиков: `docs/project-context/09_user_research/` —
`survey_responses.csv` (28 записей, собраны 3–6 сентября 2026) и `README.md` с разбором.
Все числа отчёта пересчитаны из CSV при аудите документации и сошлись, включая производные
объединения вариантов и разрезы по подгруппам.

**Что он устанавливает:** из 28 респондентов 20 имеют опыт автономного режима; чаще всего
отмечены непонимание последствий действия агента и страх утечки данных (по 13 из 20), реже —
лишние подтверждения (8 из 20); подтверждения обязательны для работы с секретами (16 из 20),
отправки данных наружу и sudo (по 14); Claude Code используют 18 из 20.

**Что он не устанавливает:** спрос, готовность платить, эффективность OPENMAGI. Выборка мала
и с неизвестным отбором — один ответ двигает долю на 5 пунктов. Интервью, наблюдений за
реальными сессиями и телеметрии нет.

**Разрыв, который он вскрыл:** из шести свободных рассказов о неприятных случаях ни один не
описывает атаку, половина — про ошибку агента и выход за рамки поручения. Датасет бенчмарка
устроен наоборот: 90 атакующих кейсов против 30 контрольных, а «сделал не то, о чём просили»
покрыто одной категорией `excessive_agency` (6 кейсов).

## Известные ограничения

Подтверждаются кодом или прогоном. Полный список ограничений сервиса — в корневом
`CLAUDE.md`, раздел «Известные ограничения / roadmap»; здесь то, что меняет прочтение
состояния проекта.

1. **44 из 1538 тестов сервиса падают на Windows-хосте** — среда, а не логика (разделители
   путей, кодировка чтения контрактов, два теста бюджета латентности). Целевая среда —
   Linux в контейнере; зелёный прогон там в рамках аудита не воспроизведён.
2. **Конфликт fail-open / fail-closed не решён.** Сервис жёстко fail-closed, клиент по
   умолчанию fail-open (`onUnavailable: "allow"` в `adapters/packages/core/src/config.ts`).
   Пока владелец продукта не выбрал вариант, утверждение «`allow` по ошибке невозможен»
   верно для сервиса, но не для системы.
3. **Документация адаптеров отстала от сервиса.** `adapters/README.md` и docstring
   `packages/core/src/protocol.ts` утверждают, что маршрута `inspect` на стороне гарда нет и
   что поле `rules` игнорируется. Оба утверждения неверны с v3.
4. **Поле профиля `rules` не читается нигде.** Оператор может написать правила в YAML, и они
   молча не сработают: правила приходят только в запросе.
5. **Решение теряется при падении между ответом и персистентностью** — сознательный размен
   латентности на полноту журнала.
6. **`GET /v1/decisions` не разграничен по владельцу ключа.** Фильтр `key_id` есть, но любой
   действующий bearer читает всю ленту целиком, включая `raw` и `user_request`.
7. **`AGENTGATE_TOKEN` на non-localhost принимается наравне с ключами**, вопреки более
   строгой формулировке `docs/superpowers/service/specs/api-keys.md`. Отклонение сознательное
   и задокументировано в docstring `agentgate/api/deps.py`.
8. **Вызов без `session_id` берёт workspace из своего `cwd`.** Привязка к сессии закрыла дыру
   только для сессионных вызовов.
9. **Ступень 2 без ретраев, один таймаут.** При недоступности провайдера всё, что не решила
   ступень 1, становится `ask`: сервис остаётся безопасным, трение растёт.
10. **Датасет написан командой целиком.** Все 120 кейсов помечены `dataset_source: team`;
    импортированного корпуса в наборе нет, поэтому ASR измерен против собственных
    представлений об атаках.
11. **Контрольная группа — 30 кейсов.** Резолюция FP и Friction — 1/30, то есть один кейс
    двигает метрику на 3,3 пункта.
12. **Результаты прогонов не версионируются.** `benchmark/results/` в `.gitignore`; в
    репозитории лежит только отчёт с числами, но не сами артефакты.
13. **Сайт `openmagi.ru` не показывает измеренных цифр** — соответствующие поля в
    `frontend/site/config.js` остаются заглушками (`null` рендерится как «——»).

## Что можно показать на демонстрации

С указанием, чем подтверждается.

- **Живой сервис.** `https://api.openmagi.ru/healthz` отвечает прямо сейчас; `/v1/decisions`
  без токена даёт 401.
- **Три исхода через curl.** `contracts/curl-examples.md` плюс `contracts/examples/` —
  реальные запросы и ответы развёрнутого сервиса по обоим маршрутам.
- **Скорость детерминированной ступени.** Тест бюджета (`tests/rules/test_latency.py`) и та
  же цифра в поле `latency_ms.stage1` живого ответа: в прогоне p50 — 0 мс.
- **Устойчивость hard-deny к обфускации.** Табличные тесты `tests/rules/hard_deny/test_rules.py`
  покрывают `$(…)`, `eval`, переменные, base64, heredoc, обёртки.
- **Fail-closed.** Достаточно указать в профиле недоступный `base_url`: всё, что не решила
  ступень 1, приходит как `ask`.
- **Маскирование секретов и инъекций.** `POST /v1/inspect` на подготовленном выводе:
  `contracts/examples/inspect-redact-secret.json`, `inspect-mask-with-history.json`,
  `inspect-drop.json`.
- **Гейт внутри работающего харнесса.** Плагины из `adapters/`; для быстрого показа —
  `packages/mock-guard` и `recon/mock-llm.mjs`.
- **Цифры бенчмарка** — только с оговоркой «один прогон, наш датасет, 6 сентября 2026», и
  вместе со строкой про родной auto mode: скрывать её нельзя, она в том же прогоне.

**Чего показывать нельзя:** превосходства над Claude Code auto mode (измерение говорит
обратное), стоимости в деньгах (не измерена), полезности на исполняемых задачах (ActBench не
запускался), защиты от slopsquatting (модуль — заглушка), ветки SAFE RECOVERY (не
существует), работы в многоворкерном режиме (состояние сессии не общее).
