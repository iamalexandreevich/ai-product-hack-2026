# Auto Mode: что показал опрос

Аналитический отчёт для команды OPENMAGI • 6 сентября 2026 года

**Главный вывод.** Ответы дают основание проверять ценность автономии с понятными границами: агент выполняет задачу, пользователь понимает последствия и сохраняет контроль над чувствительными действиями. Уменьшение лишних подтверждений - одна из составляющих этой ценности.

В этой выборке непонятные последствия и страх утечки данных отмечены чаще, чем чрезмерные подтверждения: по **13 из 20** против **8 из 20**. Среди желаемых улучшений близки безопасное продолжение после блокировки (**6**), понятный журнал (**5**) и объяснение опасности (**5**). Это разведочное подтверждение проблем и направление для прототипа, но ещё не подтверждение спроса или эффективности OPENMAGI.

Источник всех чисел выше: приложенные «Ответы опроса», столбцы F и I; подробности источника приведены в конце отчёта.

Для вопросов о проблемах, сценариях, подтверждениях и улучшениях знаменатель **20**. Для причин неиспользования - **8**. Всего в файле 28 записей за **3-6 сентября 2026 года**. В отчёте анализируется приложенный снимок ответов. Способ приглашения, генеральная совокупность, роли, стаж и география участников неизвестны. Одна запись условно рассматривается как один участник: уникальность людей по этому файлу подтвердить нельзя. Профессия участников принимается из описания пользователя.

**Как пользоваться выводами.** Частоты надёжно описывают предоставленные записи. Объяснения причин, приоритеты реализации и прогноз поведения ниже обозначены как интерпретации или гипотезы. Проценты не следует переносить на всех программистов.

**Продуктовая гипотеза.** Границы разрешений стоит задавать по конкретному действию, цели и среде: чтение БД / изменение данных; подготовка миграции / применение; локальная правка / изменение рабочей инфраструктуры; подготовка сообщения / отправка. Желаемая самостоятельность в категории не означает согласие на любое действие внутри неё.

Например, один участник одновременно хочет автономную установку зависимостей и подтверждение новых пакетов. Это может отражать различие между известной зависимостью и новым выбором пакета, но причина в анкете не выяснялась. Неотмеченный пункт также не равен явному разрешению: особенно нельзя заключать, что остальные 18 человек одобряют любую установку пакетов.

Свободное описание неприятного случая дали **6 из 20** участников с опытом. Остальные 14 оставили поле пустым: это не свидетельство отсутствия неприятного опыта. Ни один из шести текстов не содержит достаточно данных, чтобы установить намеренную атаку или prompt injection.

Источник: «Ответы опроса», J3, J5, J10, J13, J26, J29. Случаи пересказаны; причины, ущерб и предлагаемые проверки не подтверждены журналами. Для MR пользователь не уточнил, было ли явно запрещено отвечать; для пакетов не установлена вредоносность.

**Вывод для позиционирования.** Стоит проверять защиту от ошибок агента и действий за пределами поручения наряду с противодействием атакам. В двух рассказах прямо фигурируют операции с БД, но шесть добровольных рассказов не позволяют оценить распространённость потери данных. Гейт решений сам по себе не гарантирует качество кода, производительность GPU или успешность задачи.

### Какие интеграции разумно проверить первыми

Claude Code указали **18 из 20**, OpenAI Codex - **11**, Cursor Agent - **5**; каждый из остальных шести названных инструментов - по одному. Несколько агентов используют **14 из 20**. Источник: столбец D, множественный выбор.

Для пилота **в этой группе** логично проверить Claude Code, затем Codex и Cursor. Это вывод о доступной аудитории тестирования, а не о рыночных долях или простоте интеграции. Вопрос спрашивал, какими агентами пользуются вообще; он не связывает конкретную проблему или настройку автономии с конкретным продуктом. Сравнивать безопасность харнессов по этим ответам нельзя.

## 4. Что это означает для OPENMAGI

Ниже - предлагаемые проверки продукта, выведенные из опроса. Они не описывают текущее состояние реализации и не доказывают, что определённая архитектура решит выявленные проблемы.

| Приоритет проверки | Основание в ответах | Какой результат проверить |
| --- | --- | --- |
| Понятное решение о чувствительном действии | 13/20 не понимают последствия; 16/20 хотят подтверждать секреты | Пользователь понимает, что изменится, что выйдет наружу и почему требуется решение |
| Журнал действий и решений | 5/20 выбрали журнал главным улучшением | По записи можно восстановить действие, основание решения и результат |
| Безопасное продолжение после блокировки | 6/20 выбрали альтернативный путь | Задача продвигается к цели без повторения запрещённого эффекта |
| Границы по действию и среде | Разные ответы для файлов, секретов, БД и инфраструктуры | Политика различает подготовку и исполнение, чтение и изменение |
| Снижение лишних остановок | 8/20 жалуются на подтверждения; 7/20 - на безопасные блокировки | Уменьшается число ненужных вмешательств при сохранении ограничения опасных действий |

Источник оснований: «Ответы опроса», F-I. Порядок - аналитическое предложение, не голосование за дорожную карту. Стоимость реализации и качество существующих механизмов в опросе не измерялись.

### Как измерять пользу в пилоте

- **Безопасность:** доля заранее размеченных опасных действий, ошибочно разрешённых системой; отдельно результат тестовых атак. Опрос не измеряет ASR.
- **Лишние вмешательства:** ненужные запросы подтверждения и блокировки среди действий, заранее оценённых как допустимые в заданном контексте.
- **Продолжение после блокировки:** доля подходящих задач, завершённых разрешённым альтернативным способом; блокировка вреда без выполнения задачи не считается завершением.
- **Понятность:** способен ли пользователь правильно назвать последствие действия и причину решения; время и ошибки при принятии решения.
- **Полезность и издержки:** выполненные задачи, активное время пользователя, задержка гейта, стоимость запросов и повторных попыток.

Это предложенные метрики, не результаты измерений. Пороги успешности надо определить до пилота под конкретные задачи. Анкета не обосновывает ни допустимый процент ASK, ни тезис «при 30% подтверждений пользователь отключит защиту».

**Рабочая формулировка ценности для проверки:** «OPENMAGI помогает агенту работать самостоятельно в согласованных границах: объясняет чувствительные действия, сохраняет журнал решений и поддерживает безопасное продолжение после блокировки». Эту формулировку следует сверять с фактически работающими функциями перед использованием в презентации.

## 5. Ограничения и альтернативные объяснения

**Маленькая выборка с неизвестным отбором.** Один ответ среди пользователей меняет долю на 5 процентных пунктов. Способ приглашения и число приглашённых не указаны; долю отклика и представительность оценить нельзя. Оснований рассчитывать обычную выборочную погрешность для населения здесь нет. AAPOR ограничивает применимость такой погрешности вероятностными выборками. Источник: [AAPOR, Margin of Sampling Error/Credibility Interval](https://aapor.org/wp-content/uploads/2023/01/Margin-of-Sampling-Error-508.pdf).

**Анкета направляет внимание на безопасность.** Вопрос о том, что «НЕ нравится», предполагает поиск недостатков, а сохранённые варианты улучшений относятся к контролю и безопасности. Качество кода, скорость и стоимость не представлены среди выбранных стандартных улучшений. Полного списка вариантов и настроек формы нет: нельзя утверждать, что отсутствовали «всё устраивает» или «другое». Формулировки, варианты и их порядок могут влиять на ответы; точный размер этого влияния здесь неизвестен. Источник методологии: [Pew Research Center, Writing Survey Questions](https://www.pewresearch.org/writing-survey-questions/).

**Разные смыслы автономного режима.** Анкета объединяет Auto Mode и аналоги, но не фиксирует конкретный режим разрешений, версию продукта, модель и среду. Категория «использовал несколько раз» не исключает недельного использования: её выбрали 4 человека, и все 4 указали несколько раз в неделю. Один «регулярный» пользователь ответил «реже». Записи не переклассифицированы. Источник: столбцы B и E.

**Проблема, страх и выбор улучшения измеряют разное.** 13/20 боятся утечки, но рассказов о подтверждённой утечке нет. 4/20 отметили разрешение опасных действий, однако число и тяжесть случаев неизвестны. Столбец I содержит по одному приоритету, поэтому редкий выбор усиленной защиты секретов не измеряет её общую важность. Неотмеченная галочка не является надёжным отрицанием; это ограничение формата обсуждается в исследовании [Pew Research Center о select-all-that-apply](https://www.pewresearch.org/methods/2019/05/09/when-online-survey-respondents-only-select-some-that-apply/).

**Противоречивый ответ не меняет основные границы.** В H29 одновременно выбраны секреты, инфраструктура и полное доверие. Если исключить эту строку только из анализа подтверждений, остаются: секреты 15/19; отправка наружу и admin-права по 14/19; production-код и инфраструктура по 11/19. Значимых для продуктового направления перестановок нет. Утверждать, что «5% полностью доверяют агенту», некорректно.

**Подгруппы слишком малы для устойчивых сравнений.** На лишние подтверждения жалуются 3 из 4 пробовавших и 5 из 16 регулярных пользователей. Последствия непонятны 1 из 4 и 12 из 16 соответственно. Возможны различия опыта, задач, настроек и самоотбора; нельзя заключать, что подтверждения вызывают отказ от режима. Среди неиспользующих 3/8 выбрали недоверие, 2/8 - незнание возможности, 2/8 - отсутствие необходимости, 1/8 - «не дошли руки». Безопасность не объясняет все причины неиспользования. Источник: столбцы B, C и F.

## 6. Следующий шаг и формулировка для защиты

**Практический следующий шаг - проверить наблюдаемое поведение на прототипе.** Например, провести 6-8 интервью и коротких заданий с участниками разных групп. Это предложенный объём разведочного этапа, не статистический норматив и не обещание репрезентативности.

1. Разобрать последний конкретный эпизод: задачу, разрешения, действие агента, вмешательство и последствия. Начать со свободного рассказа до списка возможных проблем.
2. Дать сопоставимые сценарии: создание миграции / применение; известная / новая зависимость; чтение данных / отправка наружу. Зафиксировать, где пользователь ожидает самостоятельность.
3. Сравнить на одинаковых задачах базовый режим и прототип с понятным решением, журналом и безопасной альтернативой. Менять порядок условий между участниками, чтобы уменьшить эффект обучения.
4. Проверить фактическое завершение задач, ненужные вмешательства и понимание риска. Отдельно выяснить, согласен ли человек продолжить пользоваться продуктом и в каком формате; готовность платить пока неизвестна.

### Что можно сказать на защите

«Мы собрали 28 ответов, из них 20 - от людей с опытом автономного режима. По 13 из этих 20 участников отметили сложность понимания последствий и страх утечки данных, 8 - слишком частые подтверждения. Самые частые выбранные улучшения - безопасное продолжение после блокировки, понятный журнал и объяснение опасности. Результаты дают основания проверять продуктовую гипотезу управляемой автономии; готовность пользоваться отдельным решением и его эффективность мы должны проверить в пилоте».

Источник чисел: «Ответы опроса», столбцы B, F и I. Это формулировка по исследованию, а не заявление о готовности продукта.
