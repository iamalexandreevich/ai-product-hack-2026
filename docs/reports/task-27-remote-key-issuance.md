# Task 27 — выпуск API-ключей на сервере из локального Makefile

Дата: 7 сентября 2026. Спека: `docs/superpowers/service/specs/2026-09-07-remote-key-issuance-design.md`.

## Что построено

Три цели в `service/Makefile`: `make key LABEL=… [EXPIRES=…]`, `make keys`, `make key-revoke ID=…`. Каждая запускает существующий CLI `python -m agentgate keys` внутри контейнера `gate` на сервере через тот же SSH-псевдоним и тот же набор compose-файлов, что и `make deploy`. Ничего нового в сервисе, контракте и базе не появилось.

## Доказательства TDD

`tests/test_makefile_keys.py` (6 тестов, `make -n`): цель `key` содержит `exec -T gate … keys create --label '<label>'`, `--expires` только при `EXPIRES`; `keys` и `key-revoke` собирают `list` и `revoke <id>`; `key` без `LABEL` и `key-revoke` без `ID` падают до обращения к серверу. Первая версия проверяла аргументы shell-`if`, и два теста упали, потому что `make -n` shell не исполняет; проверка перенесена на `$(if …,,$(error …))`, что заодно гарантирует остановку до `ssh` в любом режиме. Все шесть проходят.

## Решения

- Выбрана минимальная форма из `api-keys.md` («скрипт на сервере»): получатель ключа — оператор с SSH. Инвайты и эндпоинт выпуска отложены до запроса «ключ без доступа к серверу».
- `-T` у `exec` обязателен: без TTY stdout ключа остаётся чистым для подстановки.
- Метка в одинарных кавычках; метка с `'` не поддерживается, ограничение описано в README.

## Не проверено

Живой вызов `make keys` на `api.openmagi.ru` из этой сессии не выполнен: SSH-команда заблокирована классификатором автоматического режима. Проверить руками одной командой `make keys` из `service/`.
