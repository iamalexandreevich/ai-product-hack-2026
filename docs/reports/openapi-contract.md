# OpenAPI-контракт `contracts/openapi.yaml`

## Что это

Единый OpenAPI 3.1 документ HTTP-контракта AgentGate v1 — то, что отдаётся внешнему
разработчику. Покрывает четыре эндпоинта раздела 4 спеки:

| Метод | Путь | Статус |
|---|---|---|
| `POST` | `/v1/decide` | реализован, контракт устоялся |
| `GET` | `/v1/decisions` | **не реализован**, форма предварительная |
| `GET` | `/v1/profiles/{id}` | **не реализован**, форма предварительная |
| `GET` | `/healthz` | **не реализован**, форма предварительная |

Кроме схем, в документе прописано прозой то, что клиент иначе сделает неправильно:

- любое решение — **HTTP 200**, включая `deny` и `ask`; отказ не является ошибкой транспорта;
- fail-closed: любая ошибка, таймаут, невалидный ответ или невалидный запрос → `ask`,
  `allow` по ошибке невозможен;
- `deny` всегда несёт `reason` и `suggest`;
- лимиты запроса, в том числе `raw` ≤ 32768 **байт** UTF-8 (не символов: кириллица —
  2 байта на символ), а `user_request` не отклоняется, а обрезается до 2048 символов
  **с сохранением хвоста**;
- `raw` обязателен для `tool: shell`; `args.paths` и `args.domains` для `shell`
  игнорируются — сервис извлекает их сам из AST команды;
- без `session_id` нет ни счётчиков, ни кэша, решение пишется с null-сессией;
- профили живут на сервере, харнесс политику не видит;
- bearer-токен описан как **необязательная** схема: OpenAPI не умеет выразить правило
  «обязателен при не-localhost биндинге», поэтому оно изложено прозой в описании схемы
  безопасности.

Для `/v1/decide` даны три пары «запрос → ответ» (`allow`, `deny`, `ask`) с русскими
`user_request`, плюс четвёртый пример ответа — fail-closed `ask` на невалидный запрос.

## Что предварительное

Три из четырёх эндпоинтов ещё не написаны. В описании каждого из них стоит
`**NOT YET IMPLEMENTED — shape provisional.**`, и они собраны под тегом `provisional`.
Их query-параметры и путь взяты из спеки, а вот конверты ответов спекой не
зафиксированы: схемы `DecisionListResponse`, `DecisionRecord`, `Health` и `Error`
написаны руками, помечены `PROVISIONAL` в собственном `description` и оставлены
открытыми (`additionalProperties: true`). Строить интеграцию на них пока нельзя.

Исключение: схема `Profile` — она сгенерирована из живой модели
`service/agentgate/profiles/schema.py`, поэтому имена и типы полей точные;
предварительным остаётся только то, как эндпоинт их завернёт.

## Как регенерировать

Схемы в `components.schemas` **не пишутся руками** — они генерируются из pydantic-моделей
(`service/agentgate/api/schemas.py`, `service/agentgate/profiles/schema.py`), как и
`contracts/*.schema.json`. Руками пишется только проза: описания эндпоинтов, описания
полей и примеры.

```
cd service
uv run python scripts/export_openapi.py
uv run pytest tests/test_contracts.py
```

Тест `test_openapi_matches_generated_document` падает, если закоммиченный YAML разошёлся
со свежесгенерированным, — забыть регенерацию после правки модели не получится.
Дополнительно проверяется, что все `$ref` разрешаются, что примеры в документе
действительно проходят валидацию моделями `DecideRequest`/`DecideResponse`, что
нереализованные эндпоинты помечены, и что bearer-схема объявлена необязательной.
Описания полей наложены оверлеем с проверкой имён: если поле модели переименовали или
удалили, экспортёр падает с `RuntimeError`, а не оставляет устаревшее описание.

Документ проверен валидатором `openapi-spec-validator` 0.9.0
(`OpenAPIV31SpecValidator`) — 0 ошибок. Валидатор запускается разово через
`uv run --with openapi-spec-validator`, в зависимости сервиса он не добавлен.
