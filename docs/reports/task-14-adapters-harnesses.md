# Task 14 — Направление 1: плагины Gate для шести харнессов

Дата: 4 сентября 2026. Всё в `adapters/`. Гард — не наша зона; мы делаем адаптеры, патчи,
сборку и инсталлер.

## Что построено

Плагин гейтит **каждый** тулкол (PreToolUse → `POST /v1/decide`, `allow | ask | deny`) и
фильтрует **каждый** результат тула (PostToolUse → `POST /v1/inspect`, `pass | mask | drop`)
до попадания в контекст модели. Режимы `auto | ask | allow | off` переключаются Shift+Tab
и `/gate`, мгновенно, без перезапуска.

| Харнесс | Версия | Точка входа | Патч |
|---|---|---|---|
| opencode 1.x | 1.17.18 | плагин, хук `permission.ask` | **нужен** |
| Kilo CLI | 7.5.6 | тот же плагин (форк) | **нужен, свой** |
| opencode 2.0 | beta-17823 | `Plugin.define` + `ctx.tool.hook` | нет |
| Pi | 0.84.4 | `pi.on("tool_call"/"tool_result")` | нет |
| Codex CLI | 0.146.0 | плагин с `hooks.json` | нет |
| DeepSeek Harness | 0.1.1-rc.2 | cordis `tools/pre-execute`/`post-execute` | нет |

Пакеты: `core` (вся логика, ноль зависимостей от харнесса), пять адаптеров, `installer`
(`install/status/doctor/mode/uninstall`), `mock-guard`. Плюс `build/` — патчи по харнессам
и сборка пинованного билда.

## Доказательства

**Автотесты:** 106 зелёных (`node --test`, без сети наружу; каждый поднимает свой эфемерный
mock-guard). Покрыты: маппинг тулов, режимы, лимиты по байтам, кэш `in`, идемпотентный ключ,
политика fail-open/closed, JSONC-правки инсталлера, все шесть адаптеров.

**Живые прогоны** — не по логам плагина, а по ленте решений гарда (`GET /v1/decisions`) и по
наблюдаемому эффекту. Точные шаги — `adapters/docs/RUNBOOK.md`.

- deny: `rm -rf` заблокирован, каталог физически пережил прогон, агент продолжил ход;
- mask: инъекция в файле заменена на `[gate: instruction-like text removed]`, до модели
  дошёл именно переписанный текст (проверено чтением следующего запроса);
- allow: read-only проходит без промпта.

**Патч жив — A/B, а не «вроде работает».** Плагин кладёт в каждый запрос флаг
`metadata.patched`. На стоковом Kilo — `False` во всех решениях (хук мёртв), на патченном
билде — `True`, включая решение `deny`.

## Находки ревью и как закрыты

1. **`permission.ask` объявлен, но не вызывается** ни в opencode 1.x, ни в Kilo (перечислены
   все `trigger(...)` в бинарниках). → Патч оживляет хук через reviewer. Без патча остаётся
   рабочий fallback с оговоркой (промпт мигает).
2. **Патч opencode не ложится на Kilo** — форк переписал permission-модуль (557 строк против
   223). → Отдельный патч, патчи разведены по `build/patches/<harness>/`.
3. **Инсталлер молча деградировал в fallback**: манифест указывал в `/tmp`, который чистится
   при перезагрузке. → Билды переехали в `~/.local/share/gate-catalog/`, манифест в `.gitignore`
   как машинно-зависимый, поведение задокументировано в `build/README.md`.
4. **Инсталлер затирал пользовательский `permission`** в конфиге. → `fillMissing` (только
   добавляет отсутствующие ключи) + sidecar-запись для точного `uninstall`.
5. **Тулы Codex в PascalCase** (`Bash`) уезжали в `mcp_call` вместо `shell`. → Нормализация имени
   до маппинга.
6. **В dsh листенер падал молча** (`exec.agent` — сервис-прокси Cordis, его сериализация роняет
   обработчик), из-за чего тулколы шли мимо гарда. → Не трогаем `exec.agent`.
7. **`.gitignore` в корне был пуст** — `node_modules` ушёл бы в коммит. → Правила добавлены
   поверх пришедших с `origin/main`, ничего из них не потеряно.

## Принятые решения

Полный лог — `adapters/docs/DECISIONS.md` (16 пунктов), дельта к исходному ТЗ —
`adapters/docs/tz-changes.md`. Ключевое:

- **Контракт**: `POST /v1/decide` строго по `contracts/openapi.yaml`; `in`-направления в
  контракте нет, сделали `POST /v1/inspect` по аналогии, транспорт в конфиге.
- **Fail-open — это «пусть решает харнесс», а не «пропустить»**: в dsh `allow` минует штатный
  approval-seam, поэтому при недоступном гарде адаптер возвращает управление харнессу.
- **Codex 0.146 реализует не всю свою схему**: работает только `deny`; авто-одобрение вынесено
  в `PermissionRequest`, `mask` вырождается в `block`.
- **Оригинальные бинарники не трогаем**: обёртка `<h>-gate` + overlay через `*_CONFIG_CONTENT`,
  билд пинится к точной версии (общая SQLite).

## Что отложено

- **Инсталлер знает 4 харнесса из 6.** Codex и dsh ставятся руками по RUNBOOK: у Codex своя
  механика (marketplace + однократное подтверждение доверия в TUI), у dsh — правка
  `cordis.patch.yml`. Осознанно отложено.
- **Всё проверено на моках**, с настоящим сервисом связка не гонялась.
- **Только `darwin-arm64`**, CI-матрицы билдов нет. Windows и Claude Code — вне scope.

## Требует решения владельца продукта

**Fail-open на клиенте против fail-closed в сервисе** (`adapter-contract-gap-analysis.md`,
помечено как нерешённое). Адаптер по умолчанию fail-open: недоступен гард → работаем дальше.
Сервис гарантирует, что `allow` по ошибке недостижим. Гарантия снимается снаружи: остановил
гард — разрешено всё. `GATE_FAIL_CLOSED=1` / `on_unavailable: deny` переключают адаптер в
строгий режим, но это **не** умолчание. Нужен выбор: сделать строгий режим умолчанием,
требовать его как условие поддерживаемой конфигурации, или принять размен и убрать
утверждение про недостижимый `allow` из описания системы в целом.

**Идемпотентность.** Адаптер шлёт `Idempotency-Key: sha256(harness|session|call_id|direction)`.
Сервис его не читает: повтор из-за таймаута создаст вторую строку решения и дважды сдвинет
счётчики сессии, приблизив эскалацию.
