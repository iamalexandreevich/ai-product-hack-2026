# Задача 24: AgentGate v4 — Context Guard: спаны от модели и маскирование секретов

Ветка `feat/v4-context-guard` (worktree `…/ai-product-hack-2026-wt/v4`, от `main` `8ab67c5`). Спека `docs/superpowers/service/specs/2026-09-05-agentgate-v4-context-guard-design.md`, план `docs/superpowers/service/plans/2026-09-05-agentgate-v4-context-guard.md` (13 задач в четырёх волнах). Что изменилось для интегратора, аддитивно к v3:

- `InspectRequest` не изменился. `InspectResponse` получил `spans` (координаты замаскированных и отредактированных строк, без текста) и `redacted` (сколько значений секретов скрыто). `output` при `mask` по-прежнему авторитетен.
- Секреты в результате инструмента редактируются по значению до всего остального: `AWS_SECRET_ACCESS_KEY=[gate: secret redacted]`, `Authorization: Bearer [gate: secret redacted]`, PEM-блок схлопывается в `[gate: private key redacted]`. Имя ключа и строка остаются, редакция не двигает порог `drop`. Новый `rule_id` — `inspect.secret`.
- Классификатор ступени 2 отвечает словами `pass | mask | drop`, списком спанов строк и списком `unredact`; сервер валидирует спаны против отправленных сегментов и применяет той же маской. Маска целиком от модели — `rule_id: inspect.semantic`.
- Профиль: `inspect.classifier` получил режим `always`, появились `inspect.secrets` (по умолчанию `on`) и `inspect.model_budget` (окна вокруг находок, сколько символов уходит модели).
- Ключ кэша inspect включает дайджесты задачи и истории и политику кандидатов по энтропии. `raw` в ленте и JSONL — текст после редакции; исходное значение не хранится нигде.

## 2. Что построено, по задачам

- **0.** `Action.redact`; `Finding` с `line_end`, `rewritten`, `candidate_key`, `kind`, `confidence`, свойством `last`; `Span` со сбросом `confidence` при `source: detector`; `InspectResponse.spans/redacted`, `DecisionRecord.spans/redacted/spans_rejected`, колонки и миграция `0006`; `ModelBudget`, `InspectSettings.classifier: always`, `.secrets`; `StructuredOutput.max_tokens` (inspect — 1500); `Segment`/`Segments` с `covers`; `InspectOutcome` без `replacement`; фейк принимает `pass|mask|drop`, спаны и `unredact`, и по-прежнему буквы v3.
- **1.** `mask.apply`: `resolve` по приоритету `redact > clean > mask` на строке, диапазоны (PEM схлопывается в ответе), `redacted_lines` с сохранением нумерации, `spans` и `redacted` в `Stage1Outcome`, порог `drop` считает только `mask`.
- **2.** `secrets.scan_secrets(output)`: таблица форм (AWS, GitHub, GitLab, OpenAI/Anthropic, Slack, JWT с проверкой заголовка, PEM, HTTP-заголовки, `имя=значение` с чувствительным именем), кандидаты по энтропии с белым списком и `IGNORED_KEYS`, провенанс-политика `entropy_candidates_allowed`; корпус ложных срабатываний из 40 строк; восемь латентных корпусов под 5 мс p50. Горячий путь — префильтр по всему тексту в C (одна `str.find` на иглу с прыжком к следующей строке, один якорный regex для кандидатов), номера строк подсчётом `\n` кумулятивно.
- **4.** `segments.build`: окна `window_lines` вокруг каждой находки, склейка пересекающихся и соседних, нарезка по `segment_max_lines`, обрезка по `max_segments` и `max_chars` с частичным последним сегментом, счётчики пропущенного; без находок — начало вывода.
- **5.** `InspectOutput` (`verdict`, `spans`, `unredact`, `reason`, `extra=forbid`), роль модели с объяснением координат и запретом на `secret`, `[SEGMENTS]` с заголовками `#N lines A-B` и построчным экранированием, строка `omitted`, `[CANDIDATES]` с именами ключей без значений, голый `[FLAGS]` при чистой ступени 1.
- **7.** `spans.validate`: шесть условий §4.5, слияние пересечений одного вида, отбрасывание позднего при разных, спаны становятся `Finding` с `rule_id: inspect.semantic`.
- **9.** `inspect_cache_key` с `task_digest` и `history_digest`; диалог строится один раз в `_resolve`.
- **10.** `Inspection.spans/redacted/spans_rejected/redacted_output`; `raw` записи — редактированный текст; попадание в кэш переносит спаны и редакцию, но не `spans_rejected`; спаны обходят Postgres через JSONB без правок репозитория.
- **8.** `reconcile.py`: капы §4.7 как чистая функция (`drop` ступени 1 стоит, `pass` снимает все `mask` и никогда `clean`/`redact`, модель добавляет спаны и не снимает редакцию, `unredact` только для кандидатов, `mask` без спанов — ошибка `empty-spans` с откатом); `Inspector`: секреты → детекторы → `apply` → сегменты из редактированных строк → классификатор по режиму → `reconcile`; `_cap_stage2` удалён. Приёмка §7.3 на маршруте: `printenv` с `AKIA…` без значения в ответе, записи и JSONL; повтор по `Idempotency-Key` отдаёт редактированный ответ; перефразированная инъекция под `always` → `mask` со спанами модели; замаскированный результат в `history` следующего `decide` не доносит инъекцию до промпта; запрос v3 получает ровно два новых поля.
- **12.** README сервиса (форма секрета, секция `inspect` профиля), карта модулей и закрытый список слотов промпта в `service/CLAUDE.md`, раздел v4 в `contracts/README.md`, корневой `CLAUDE.md`.

## 4. Находки ревью и как закрыты

**Исполнители нашли в плане.** Два теста маски из плана использовали входы, пересекающие порог `drop` (три строки, две флагованы), входы расширены до пяти строк с сохранением сути. Корпус латентности `token_lines_dense` (каждая строка — настоящий секрет) недостижим для любого кода: конструирование `Finding` на десять тысяч строк стоит ~7,5 мс; разделён на два корпуса, зафиксировано отступлением 11 плана. Тест бюджета ступени 1 измерял всю `inspect()` и ловил `detect_workspace` (~25 мс на несуществующем пути); переведён на `latency.stage1_ms`. Корпус в 256 КБ перешагивал `OUTPUT_MAX_BYTES`; цикл остановлен до порога.

**Ревью соответствия волны 1.** Критично: промежуточное состояние ветки роняло маршрут в 500 при ответе модели `mask` поверх `drop` ступени 1 (в v3 случай был недостижим). Задача 8 закрыла это структурно через `reconcile`, раунд правок закрепил тремя тестами на трёх уровнях. Важно: замена латентного корпуса не была записана в отступления — записана.

**Ревью качества волны 1.** Критично: ключ кэша нёс только `kind` провенанса, а политика кандидатов зависит от `path` и `command`; `cat .env` и `cat config.sample` с одинаковым выводом делили ключ, и чтение `.env` могло получить нередактированный вердикт. Закрыто шестым компонентом ключа (флаг кандидатов, считается один раз в `_resolve`) и тестом на исходный сценарий в обоих порядках. Важно: подсказки заголовочной формы были строже её регулярки (`X-Api-Key\t:` пропускался) — иглы без двоеточия, регулярка та же, латентность без регрессии, плюс тест инварианта подсказок; строка провенанса в промпте не редактировалась (`curl -H "Authorization: Bearer …"`) — добавлен `redact_line`, применяется ко всем значениям провенанса; докстринг `Span` уточнён: координаты `output` запроса. Мелочи: `MODEL_SPAN_KINDS` выводится из `SpanKind`, `_reason` считает строки, докстринг `resolve` про `id()`, кап головного окна сегментов, слабый тест системного промпта заменён, импорты в тестах подняты. Единственная структурная перестановка раунда: `ModelSpan` переехал из `classify.py` в `spans.py`, чтобы не замкнуть цикл импортов.

## 4а. Финальное ревью всей ветки

Два ревьюера смотрели задачу 8 и раунд правок 1 (первый запуск ревью соответствия завис без результата и был перезапущен с лимитом шагов).

**Качество: NEEDS FIXES → раунд правок 2** (`034db50..51fb9ab`). Критично: шестой компонент ключа закрыл политику кандидатов, но в промпт ступени 2 уходит вся строка провенанса, а в ключе был только `kind`: `pass` для `url: docs.example/guide` повторялся для `url: evil.example/payload` с тем же выводом. Ключ теперь несёт дайджест всего `provenance.model_dump_json()`; флаг кандидатов остался отдельным компонентом, потому что зависит ещё и от workspace. Важно: причина модели при `pass` вытесняла причину ступени 1, когда редакция удерживала вердикт на `mask` — теперь при выжившей маске остаётся причина ступени 1; модельный `drop` на чистой ступени 1 приходил без `rule_id` — `inspect.semantic`; ветка `empty-spans` пересчитывала `apply` впустую — возвращает исход ступени 1; третья копия идентификаторов правил в `inspector.py` заменена импортами; `Inspector.inspect` разбит на `_stage1` и `_inspection`; карта модулей `service/CLAUDE.md` и README поправлены под `NEEDLE_FORMS` и переезд `ModelSpan` в `spans.py`.

**Соответствие спеке: ЕСТЬ РАСХОЖДЕНИЯ, критичных нет → правка 3** (`fix(inspect): a model pass lifts only …`). Важно: `pass` модели снимал и подпороговый `inspect.encoded`, а §4.7 разрешает снимать только `inspect.injection` и `inspect.pipe-exec`; теперь `_lifted` фильтрует по `rule_id`, тест на блоб ниже порога добавлен. Заметки: `drop` теряет `spans` и `redacted` в записи — оставлено (при `drop` агенту ничего не показано, `raw` отредактирован); `raw` строже ответа после `unredact` — задокументировано на поле `redacted_output`; описание `spans` в схеме ответа повторяет, что координаты относятся к `output` запроса. Ревьюер подтвердил запуском §5 (токен в `output` и в `provenance.command` отсутствует в промпте), отступления 5/6 (координаты спанов при схлопнутом PEM) и §6 (запись, JSONL, повтор по ключу). Все девять инвариантов §7.1 и четыре критерия §7.3 закреплены поимённо названными тестами; список — в отчёте ревью в журнале `sdd/v4/`.

Итог: 1215 тестов, `exit 0`, контракты без diff.

## 5. Принятые решения

Одиннадцать отступлений от спеки перечислены в плане с причинами; коротко: сканер секретов — функция по всему тексту, а не `Detector` в цепочке; `classifier: always` зовёт модель всегда, даже если единственная находка — невидимый символ; строки сегментов экранируются по одной; `raw` и сегменты сохраняют нумерацию строк, схлопывание PEM только в `output` ответа; незакрытый PEM редактируется до конца; `spans_rejected` — третья колонка; провенансы `subagent` и `unknown` без кандидатов; `max_tokens: 1500` для inspect; латентный корпус «каждая строка — секрет» заменён.

Сверх плана, по ревью: ключ кэша несёт дайджест всего провенанса (а не `kind`, как в §4.8) и флаг кандидатов — всё, от чего зависит вердикт, включая то, что рендерится в промпт; провенанс в промпте редактируется; `pass` модели снимает только `inspect.injection` и `inspect.pipe-exec`; `ModelSpan` живёт в `spans.py`. Цена дайджеста провенанса: новое поле в `Provenance` обнуляет весь кэш inspect, что дешевле списка полей, расходящегося с промптом.

Оставлено как в спеке, несмотря на замечания ревью: пересекающиеся спаны разных видов — поздний отбрасывается целиком (§4.5 п. 3); `rule_id` смешанной маски — первая `mask`-находка по строке; `redacted = 0` на ветке `drop`.

## 6. Открытые вопросы владельцу и отложенное

1. **Умолчание `classifier`** остаётся `off`: перефразированные инъекции ловит только `always`, и он же единственный платный (§8 п. 1 спеки).
2. **`unredact` вообще**: строгий вариант «кандидат редактируется всегда» проще и безопаснее (§8 п. 2).
3. **`raw` без секретов ломает воспроизводимость бенчмарка** для строк с редакцией (§8 п. 3).
4. **Бюджет ступени 1 поднят с 20 до 25 мс** (§8 п. 4); фактически ~16 мс, запас 1,5×.
5. **Бюджет сканера 5 мс условен**: держится, пока секреты не на каждой строке; §7.2 нужен член «на находку» либо оговорка. Вывод из 256 КБ одних `authorization: Bearer …` стоит ~24 мс — свойство заголовочной регулярки, не префильтра; если полный дамп `curl -v` реалистичен, форме нужен отдельный проход.
6. **Слияние спанов разных видов** по §4.5 п. 3 отбрасывает хвост позднего спана в сторону fail-open; «не сливать вовсе» строго безопаснее.
7. **`detect_workspace` ~25 мс** на несуществующем пути — вне ступени 1 и вне спеки v4, но заметно на каждом вызове с чужим `cwd`.

Отложено: спаны в символьных смещениях, секреты на стороне `decide`, кэш ступени 2 в Postgres, taint-распространение — всё по §8 спеки. Слияние с v3.1: `main` ещё не содержит v3.1 на момент отчёта; ожидаемые конфликты при слиянии `main` в эту ветку — `profiles/schema.py`, `tests/factories.py`, `tests/profiles/test_schema.py`, `contracts/openapi.yaml` (перегенерировать), корневой `CLAUDE.md`, `contracts/README.md`.
